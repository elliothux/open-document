## 3. 创建、结构与格式

### 3.1 文档与事务

空白工作簿由 XLSX 核心生成 workbook、一个可见 sheet、基础 styles、关系和内容类型。复用 P10 的 ZIP/OPC 新增部件能力，接通 P10 扩展后的 P9 新建入口与首次保存状态。文件名不作为工作表身份。

工作表以稳定身份定位，顺序和名称是可变属性。复制/新增分配新的 sheetId、部件路径和关系 ID；移动不改变身份。至少保留一个可见工作表；删除最后可见表、非法名称和名称冲突在核心拒绝。删除活动表后返回新的有效选区。

每项结构操作先形成候选：工作簿/工作表、公式、名称、范围属性、绘图关系、计算结果与选择一起校验，再提交一次 revision/历史。历史按稳定部件路径定位 XML 编辑，工作表新增/删除、关系和内容类型已进入同一历史。撤销同时恢复引用、资源和计算状态；更广资源所有权按后续功能扩展。

`editSheet({ action: "add" })` 在指定表后新增空白表，自动分配唯一的 `SheetN` 名称、sheetId、部件路径和关系 ID，切到新表 A1。新表沿用工作簿基础样式，可继续输入、计算、改名、移动与隐藏。新增不清除已有公式缓存或 calcChain；后续内容编辑继续使用原有重算及保存规则。预算或结构保护失败不留下部件。完整签名和边界归[格式合同](references/formats.md#工作表顺序名称与可见性)。

同一入口的 `{ action: "delete" }` 删除目标表，至少保留一张可见表。删除活动表后优先选择右侧可见表，再向左查找，定位 A1；删除非活动表保留选择。失去目标的已支持引用改为 `#REF!` 并重算，保留字符串常量和共享公式组；移除该表的局部名称与内部链接，同步其余名称和视图索引。工作表、关系、内容类型、失效 calcChain 和缓存作为一项有界历史，支持精确混合撤销与保存重开。共享字符串保留条目及索引，保存时更新使用计数。引用保护沿用改名边界，未知资源引用或预算失败原子拒绝。默认 UI 删除前提交已接受的单格草稿。

`{ action: "copy" }` 复制到目标表之后，分配新身份和唯一名称，保留内容、格式、尺寸及可见性。副本的自身引用和局部名称指向新表，普通批注使用独立部件；绘图、VML 和未知身份扩展仍受保护。默认 UI 先提交单格草稿。复制、输入、改名和删除可精确混合撤销，保存后可继续编辑。完整命名及资源边界归[格式合同](references/formats.md#工作表顺序名称与可见性)。

当前 `editXlsxSheet` 与 `SpreadsheetEditor.editSheet` 支持目标索引重排及 visible/hidden/veryHidden 状态。移动不改变名称、sheetId、关系或公式文本；核心重建计算索引并同步 `localSheetId`、`activeTab/firstSheet` 和所需 `tabSelected`。隐藏活动表时优先选择右侧可见表，再向左查找；显示表会激活该表。保存重开使用首个 workbook view 的活动页。只改视图时保留公式缓存、共享字符串计数和 calcChain。默认 UI 提供前移/后移、隐藏及普通隐藏表的显示入口。完整参数与保护边界归[格式合同](references/formats.md#p5-xlsx-合同)。

同一入口支持改名，默认 UI 提供名称输入和提交。核心按公式词法位置更新跨表引用、定义名称、既有条件格式/数据验证公式和内部超链接；支持中文、空格和名称内的单引号。字符串常量、共享公式组、表身份、顺序与选区保持不变。含尚未接入引用更新的资源关系或扩展内容时拒绝改名，保留源文件。核心与 Chromium 已检查引用结果、保存重开、精确撤销，以及非法名称、重复名称和预算失败后的恢复。

结构操作遍历实际存在的稀疏单元格和区间。整行/整列选择是范围描述，不展开百万个空单元格。操作前检查单元格、公式工作量、历史、资源和输出预算，不能先创建巨大矩阵再报超限。

### 3.2 引用随结构变化

整行/整列插删已复用既有源事务，接通稀疏坐标、普通/共享公式、名称、合并、尺寸、冻结与选区、规则和内部链接、打印区域/标题及计算缓存。绝对引用随结构变化移动，删除目标产生引用错误；原生草稿、结构与后续输入可分项精确撤销。未接入变换的筛选/绘图/表格/批注等资源继续保护。实现归 `xlsx/axis-*.mbt`，签名与范围归[行列插入与删除](references/formats.md#行列插入与删除)。

单元格移位插删已沿同一结构事务接通 `insertCells/deleteCells` 与默认 UI 的四个方向。只移动选区列中的下方单元格或选区行中的右侧单元格，保留行列尺寸和冻结视图；插入格复制上侧/左侧的有效格式。跨表普通/共享公式、绝对引用、名称和内部链接共同更新，富文本、单元格格式、命名空间、源间隙注释和其他部件保留。核心已检查稀疏移动、引用边界、混合精确历史、重开、边缘丢失和预算失败；Chromium 已检查原生草稿、四向操作、独立源和 PDF。既有条件格式/验证的覆盖范围随移动带拆分，逐格保持相对/绝对和跨表引用；等价公式分组保存，同步条件格式优先顺序与验证条数。核心已检查规则删除、公式型阈值、完整历史、整列绝对规则及超限原子拒绝；Chromium 已检查独立规则源与重开。被切开的合并/链接区域及未接入资源继续保护。普通验证已接通创建/修改/清除、原生输入与粘贴校验、列表下拉、输入提示及显式警告授权，保留范围外规则、相对公式和精确历史；普通值/表达式条件格式已接通计算、差异样式、网格/PDF 与自动适配，优先级和停止规则共同生效；创建、完整规则修改/删除、优先级管理及局部清除也已接通核心/API/默认面板，保留差异样式和精确历史；两/三节点颜色刻度也已接通，支持数值、百分比、百分位和公式阈值、面板管理及同一网格/PDF 填充；普通数据条及两个阈值、条长/显示值面板和 Canvas/PDF 渐变也已接通，扩展数据条仍保护源，合同归[条件格式](references/formats.md#条件格式)。普通验证元数据不再阻止 PDF，未支持条件格式继续保护输出。验证合同归[数据验证](references/formats.md#数据验证)。实现归 [`cell-shift.mbt`](../modules/formats/src/xlsx/cell-shift.mbt)，合同归[单元格移位插入与删除](references/formats.md#单元格移位插入与删除)。

扩展现有公式语法树与 `formula-shift`，区分三种操作：复制时平移相对引用；移动内容时更新指向被移动内容的引用；插入/删除行列时变换相交/跨越的区域。绝对引用限制复制平移，不代表结构插入时永远不移动。删除失去目标的引用产生正确的引用错误，而不是指向相邻数据。

同一次变换同步处理名称、合并、结构化表、筛选/排序范围、条件格式、验证、批注/链接、打印区域/重复标题、绘图锚点与透视数据源。只在这些功能接入时增加对应处理。遇到无法解释且可能受影响的引用，拒绝该结构操作并返回原因；不能靠正则替换公式字符串或清除未知扩展完成保存。

共享公式命中后沿已有规则有界展开或重新分组。复制表时重映射局部名称、关系与图形身份，工作簿级名称按明确的冲突规则处理；重命名修改引用符号，不改字符串常量。名字和 sheet 名使用核心解析规则，覆盖引号、空格和 Unicode 名称。

### 3.3 样式、合并与冻结

### 4.2 未知公式的安全编辑范围

把“无法计算”和“无法确定引用影响”分开：

| 核心已知信息 | 可执行行为 |
| --- | --- |
| 公式与依赖均受支持 | 计算并编辑受影响区域，保存实际结果 |
| 函数未支持，但引用能完整解析 | 保留公式和导入缓存；可编辑确定无依赖联系的区域。影响该公式或依赖它的计算链时拒绝，直到对应求值能力完成 |
| 依赖范围无法确定 | 保守保护可能受影响的范围；不能证明隔离时继续整本只读，不猜测安全区域 |

格式或视图操作也要按实际语义判断是否影响公式；不能一概认为未知函数只读取数值。不得把旧缓存作为“本次已计算结果”返回。查询继续区分源码、导入缓存、已计算值与未计算原因，打印/导出沿该状态决定能否完整输出。

已支持公式采用现有依赖图增量重算。结构变化一次更新引用与依赖，再计算受影响部分；预算失败不提交半个工作簿。不先建设并行计算集群、通用插件函数注册或持久化计算缓存。

结构化表拥有稳定名称、列身份、区域、表样式和总计行。扩表/插列同时更新计算列、结构化引用与相关关系。保护设置、行列大纲、批注线程/便笺和超链接各写回所属 XML/部件，显示和 API 共同遵守操作权限。

### 透视表、切片器与时间线

核心读取原始类型值，建立字段值集合与有界聚合，不使用格式化显示文字作为分组键。保存缓存定义/记录、透视定义、关系与输出区域；刷新时重新读取源数据并更新派生单元格。不能把一份普通值矩阵标成可刷新透视表。

字段拖放只修改分析定义；一次确认生成一次事务。源数据变更将透视标记为待刷新，用户刷新后更新结果；导出说明是否存在未刷新结果。输出扩大覆盖普通单元格时，默认拒绝并要求选择空白区域，不能覆盖用户数据。

切片器/时间线连接稳定的缓存和字段身份，筛选操作更新相关透视定义与结果，保存连接部件。首批仅连接同一受支持缓存；外部连接和复杂导入变体留给 P14。相同技术路线逐步加入其他聚合，不提前实现完整 OLAP 平台。

### 图表与工作表对象

图表复用 P10 已用到的系列、轴和绘制能力，XLSX 自己维护单元格数据源、范围变化和缓存。迷你图绑定单元格区域并随行列操作更新。绘图对象使用所属 sheet 的锚点：固定位置、单元格锚定和随区域变化分别保存；核心将行高/列宽换成对象几何。

图片、图形和文本框共用资源/文字布局与 R0 图元，XLSX 保留自己的锚点、选择及层次。符号作为文本，公式对象和图标按实际已有共用能力接入；不引入另一个 React/DOM 绘图模型。

| 复制/填充/排序/分析 | revision、源/目标范围、模式或分析定义；候选整体成功后返回查询状态 |
| 输出 | 输出格式、目标表/区域、布局选项与预算；结果绑定产生它的 revision |

Web 队列处理草稿与命令顺序。UI 按格式拆出工作表菜单、公式栏、格式、数据与分析面板，复用 P9 控件、Portal、稳定快照和保存回调。默认 UI 与自定义 UI 调用相同宿主方法，React 不直接调用 raw client。大范围的选区状态只返回摘要和所需记录。

CSV/TSV 解析在核心，使用明确分隔符、编码支持范围和有界行列。缺省按文字导入；数字/日期转换由用户选择，公式执行需要明确选择，不能通过 CSV 注入公式。CSV 导出明确只有所选表/区域的文本和值；格式、图形和多表损失需要提示。以公式前缀开头的文字按明确的安全导出策略处理，并说明其对重新导入的影响。

打印设置保存到工作簿，核心计算页分割、重复标题、页眉页脚和适合页数缩放，冻结窗格不改变打印。多表输出保留顺序与各表页面设置，包含本阶段已实现的图形；不使用浏览器测量来补表格分页。CSV/PDF 输出不确认 XLSX 已保存。
