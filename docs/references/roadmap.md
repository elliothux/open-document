# 产品路线图

这是整个产品迭代的总路线图，同时列出各阶段的测试目标，不是测试平台建设清单。P0–P9 按实施顺序编号；平台优先级单独表述为浏览器优先、跨宿主后续。产品、架构与测试文档统一在父仓库；测试实现和数据私有。短期不安排发布，阶段完成以可用能力和验证证据衡量。

| 阶段 | 用户结果 | 当前状态 / 依赖 |
| --- | --- | --- |
| [P0 工程与运行底座](../implemented/p0-project-foundation.md) | 开发者可构建 SDK、在浏览器创建文本会话并执行编辑/撤销 | implemented；仅文本 POC，不是 Office 功能 |
| [P1 字体与关键能力验证](../implemented/p1-sdk-foundation.md) | 固定字体、塑形、BiDi、轮廓绘制与 PDF 候选数据路径 | implemented；依赖 P0；当前边界归 SDK/格式合同 |
| [P2 文件与格式底座](../implemented/p2-format-foundation.md) | 程序化打开 DOCX、查询有限内容、修改已知文本、保真保存；共享 ZIP/XML/OPC | implemented；真实 WasmGC 与独立 ZIP/XML 判定 |
| [P3 DOCX 预览与 PDF 输出](../implemented/p3-docx-preview.md) | 应用嵌入只读分页预览，并从同一布局导出可提取文字的 PDF | implemented；有限段落/表格/内联图片，真实 Canvas 与独立 PDF 判定 |
| P4 DOCX 编辑保存 | 命中、选区、IME、编辑、撤销与保存 | planned；依赖 P3，不包含完整 Word 功能 |
| P5 XLSX 闭环 | 网格、值、首批公式依赖、编辑、保存和基础打印 | planned；依赖 P2，按实际文本/绘图需求复用 P3 |
| P6 PPTX 闭环 | 主题/版式、基础形状/文字/图片、编辑、保存/PDF | planned；依赖 P2 和已实现绘图能力 |
| P7 PDF 输入 | 解析、预览、提取与搜索 | planned；不依赖完整 Office 编辑 |
| P8 PDF 文档操作 | 页面操作、选定批注与表单能力 | planned；依赖 P7，不隐含正文任意编辑、涂黑脱敏或数字签名 |
| P9 跨宿主与稳定性 | CLI、一个明确的非浏览器宿主、可重复构建与资源边界 | planned；早期可做探针，不预建发布文档或流水线 |

P3 的 PDF writer 不要求先实现 P7 reader。P5/P6/P7 可以在公共边界成熟后分别推进，不要求先达到完整 Word 兼容。异常输入和性能边界从底座阶段开始，不推迟到 P9。

## G0 和 P0–P3 是什么关系

[G0](../g0-foundation-review.md) 回答“参考谁、哪些机制值得借鉴、哪里有风险”，不是另一个必须完整实现的 foundation 阶段。P0–P3 已实现工程、字体、窄 DOCX 文件切片及有限视觉输出；[SDK 合同](sdk.md)拥有产品/技术边界。本路线图将 G0 的建议裁剪成实际交付顺序，各阶段拥有产品合同和验收。依赖候选通过探针前，不算已经选用的生产库。

G0 的整体图是目标职责，不是现在要创建的通用框架。当前只落地首个 DOCX 切片需要的底座；Workbook、Slides、富文本事务与精细增量系统随各自阶段再建。

### 默认执行顺序与停止点

```text
P0 工程与文本会话（已完成）
  → P1.1 字体/资源 → P1.2 塑形/cluster → P1.3 字形输出与依赖验证
  → P2.0 字节与失败合同 → P2.1 ZIP → P2.2 XML → P2.3 OPC
  → P2.4 DOCX 最小语义操作 + 无编辑/局部修改保存
  → P3.1 段落 → P3.2 页面/表格/图片 → P3.3 嵌入式预览
  → P3.4 PDF → P3.5 参考场景收敛 → P4 交互编辑
```

P1 的输入是固定字体和文本，不需要先解析 DOCX。这落实 G0 §8 的“先文本风险、再保真包编辑、最后组合”建议；按 P0 → P1 → P2 → P3 顺序实施，不再把前置探针归在后续阶段名下。后续格式分支可以复用已成熟基础，但不能跳过自身前置验收。

第一项后续工作是 P4 的命中、选区与文本命令合同。P3 已执行有限分页、固定 LibreOffice 参考和独立 PDF 提取/渲染；未验证编辑保存后的参考应用重开。字体失败仍需记录 imports、glyph/cluster 或输出反例，不偷偷改用 DOM 排版。P4 不能用 P3 只读输出的通过抵扣 IME、编辑、撤销或局部重排验收。

## P4–P9 的产品迭代与测试目标

以下是后续产品范围，进入阶段时再细化接口与首批数据；不是已经实现的承诺。

| 阶段 | 产品路径与实施顺序 | 主要归属 / 复用 | 必须拿到的测试证据 | 暂不包含 |
| --- | --- | --- | --- | --- |
| P4 DOCX 编辑 | 命中/选区 → 文本命令与事务 → IME/键盘/剪贴板 → 撤销重做 → 局部重排 → 保存 | docx 权威模型 + layout 编辑几何；web 处理平台事件和无障碍 | 中文组合输入、RTL/cluster 导航、撤销恢复、非目标内容保真、编辑后预览/PDF/重开一致；测局部编辑成本 | 全 Word UI、协作、复杂修订与所有表格编辑 |
| P5 XLSX | 稀疏工作簿/样式 → 读写 → 公式解析与受支持函数 → 依赖更新 → 网格交互 → 打印/PDF | core OPC；formats/xlsx；必要的 text/绘制能力 | 两个远距离单元格不按矩形面积分配；改依赖输入后真实重算；日期/错误传播/跨表引用、保存与撤销、打印区域 | 全函数库、宏执行、外部工作簿自动加载、全部图表 |
| P6 PPTX | 主题/母版/版式 → 场景/变换 → 文本框与图片 → 选择/编辑 → 保存/PDF | formats/pptx 独立场景；共享字体和 DisplayList | 继承、组合变换、溢出、裁剪；编辑后其他 shape 不变，未知 part 保留，页面/PDF 几何一致 | 动画播放、音视频、全 PowerPoint UI |
| P7 PDF 输入 | 文件/对象/xref → 资源与内容流 → 页面预览 → 提取/搜索 | formats/pdf reader；复用字体/图像/绘制能力，不倒用 DOCX 模型 | 结构、页面/旋转/裁剪、嵌入字体、Unicode 与坐标；损坏输入/超限；PDFium/PDF.js 独立对照 | OCR、PDF→Office、全部 PDF profile |
| P8 PDF 操作 | 页面重排/删除/合并 → 选定批注 → AcroForm 字段和外观 → 保存 | PDF 对象模型与 writer | 对象/资源可达、字段值与外观一致、非目标页面保持、外部阅读器重开 | 任意正文重排编辑、签名保持、涂黑脱敏、XFA |
| P9 跨宿主 | 无浏览器 I/O 适配 → CLI → 一个明确 runtime/语言接入 → 合同与性能对照 | 复用同一 MoonBit 核心；新增最薄宿主 | imports 与运行特性实测，输入输出/错误/取消，浏览器与 CLI 同资源下的合同对照；不以启动成功代替布局一致 | 全语言 FFI、通用运行时平台、短期发布流水线 |

每次迭代按“最小真实输入 → 产品操作 → 可用输出 → 独立断言 → 失败回归”推进。文件能力、交互能力、视觉能力分开验收；转换按具体输入/输出对声明，DOCX→PDF 成功不等于任意格式互转。

## 统一测试与性能反馈

阶段方案定义承诺；[测试规则](testing.md)定义执行与失败处理；[语料管理](corpus.md)定义输入来源；私有 manifests 和测试拥有具体 expected/golden。新增产品能力必须连同真实浏览器路径、错误路径与独立参考交付，不能只有底层单测。

从 P1 开始记录塑形、字形输出、资源与跨边界批次；P2 增加输入/实际解压/原始保留材料和输出大小；P3 已增加首次/暖布局、页面绘制与 PDF；WasmGC 峰值内存仍未可靠测量。P4/P5 再加入局部编辑与重算成本。固定样本、字体、工具链和冷暖口径，先建立基线再确定预算，不编造毫秒或包体数字。

不按未经测量的兼容率、总代码量或任意工期判断完成；每阶段明确承诺的特征、失败行为和当前限制。完整 Office 兼容、宏执行、协作、桌面外壳不进入这些阶段的默认范围。
