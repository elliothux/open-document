# 产品路线图

这是产品阶段范围的唯一路线图，不是完成清单。P1–P9 是阶段身份，与“浏览器 P0 / CLI P1”的平台优先级无关。详细执行与测试方案由私有质量仓库拥有；公开 API 与格式承诺仍以产品合同和源码为准。

| 阶段 | 用户结果 | 当前状态 / 依赖 |
| --- | --- | --- |
| P1 工程与运行底座 | MoonBit workspace、Bun packages、浏览器 Worker/WasmGC 纯文本 POC | 本地最小 POC 已验证；不是 Office 功能，未发布 |
| P2 文件与格式底座 | 有界 ZIP/XML/OPC、部件关系与未知内容保留 | planned；依赖 P1 |
| P3 DOCX 预览与 PDF 输出 | 首批段落、基础样式、表格、图片、中英混排与分页 | planned；依赖 P2，字体/塑形能力先验证 |
| P4 DOCX 编辑保存 | 命中、选区、IME、编辑、撤销与保存 | planned；依赖 P3，不包含完整 Word 功能 |
| P5 XLSX 闭环 | 网格、值、首批公式依赖、编辑、保存和基础打印 | planned；依赖 P2，按实际文本/绘图需求复用 P3 |
| P6 PPTX 闭环 | 主题/版式、基础形状/文字/图片、编辑、保存/PDF | planned；依赖 P2 和已实现绘图能力 |
| P7 PDF 输入 | 解析、预览、提取与搜索 | planned；不依赖完整 Office 编辑 |
| P8 PDF 文档操作 | 页面操作、选定批注与表单能力 | planned；依赖 P7，不隐含正文任意编辑、涂黑脱敏或数字签名 |
| P9 跨宿主与发布稳定性 | CLI、一个明确的非浏览器宿主、发布准备 | planned；早期可做探针，正式支持逐项声明 |

P3 的 PDF writer 不要求先实现 P7 reader。P5/P6/P7 可以在公共边界成熟后分别推进，不要求先达到完整 Word 兼容。异常输入和性能边界从底座阶段开始，不推迟到 P9。

## P1–P3 的实施颗粒度

- P1：工具链和模块边界 → 纯文本核心状态 → WasmGC ABI → Worker 生命周期 → 本地开发与打包。只把实际可运行部分标成可用。
- P2：字节与 ZIP 预算 → XML 命名空间与未知片段 → OPC 关系图 → 无编辑保存 → 局部修改保真。格式识别不能仅看扩展名。
- P3：固定字体与塑形 → 段落测量/换行 → 页面与基础表格/图片 → 浏览器绘制 → 可移植 PDF 输出。每个环节先有真实输入再扩展抽象。

不按未经测量的兼容率、总代码量或任意工期判断完成；每阶段明确承诺的特征、失败行为和当前限制。完整 Office 兼容、宏执行、协作、桌面外壳不进入这些阶段的默认范围。
