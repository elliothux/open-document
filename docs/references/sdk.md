# SDK 目标、技术选型与核心/宿主合同

本文维护产品目标、技术选择与职责边界。当前实现包含 [P0 文本 POC](../implemented/p0-project-foundation.md)、[P1 字体/塑形/轮廓探针](../implemented/p1-sdk-foundation.md)、[P2 窄 DOCX 读写](../implemented/p2-format-foundation.md)及 [P3 限定 DOCX 预览/PDF 输出](../implemented/p3-docx-preview.md)。交互编辑和其他格式仍属后续阶段。实际 API 与支持面见[开发说明](development.md)和[格式合同](formats.md)。

本文件拥有当前产品目标、技术选型和核心/宿主合同；实现建议与待验证的生态选择见 [G0 底座研究](../g0-foundation-review.md)，参考源码入口见[上游项目](upstream-projects.md)。研究建议不自动成为新决策或依赖承诺。

**已确定选型：MoonBit + WasmGC + TypeScript。文档逻辑尽可能在 WASM 内实现，Web/TS 层尽可能薄。**

## 1. 产品目标与优先级

### 首要平台：WASM + Web 浏览器

- 提供可嵌入现有 Web 应用的开发者 SDK，而不是完整桌面 Office 应用。
- 面向 DOCX、XLSX、PPTX，逐步覆盖预览、交互编辑、程序化读写及格式转换。
- 浏览器本地运行文档核心；基础能力不以远程转换服务、Electron 或商业 Office 服务为前提。
- 同一核心拥有解析、模型、编辑语义、计算、布局和序列化能力；Web 侧提供类型明确的 TS API 和必要视图。
- 导入、导出、布局及编辑能力分别声明支持范围。不能把“能读取”“能展示”“能无损写回”和“能编辑”混为同一兼容性承诺。
- 长耗时计算以 Worker 承载为默认实现方向，避免阻塞输入与页面交互。

平台优先级不表示首版同时达到三种格式的完整兼容。P0–P9 只表示实施阶段，不再同时用 P 编号标记平台优先级。首个格式、转换组合和功能清单按真实样本收敛；当前不承诺任意格式互转或与 Microsoft Office 完全一致。

### 次要平台：其他语言 + WASM runtime，以及 CLI

- 复用 MoonBit 核心，提供无浏览器环境的程序化读写、计算及逐步完善的转换能力。
- CLI 是其他语言接入的第一条简单路径；随后验证一个明确的 WASM runtime 和语言绑定，再按实际需求扩展。
- moonrun 用作开发、测试和首个 CLI 宿主的候选，不成为文档核心的依赖。
- 不要求各语言通过 FFI 加载原生动态库，不在浏览器优先阶段建设 native ABI、多语言 binding 生成器或通用运行时框架。
- 数据操作跨平台与视觉输出跨平台分别验收。CLI 能启动、能修改文件，不代表已支持无浏览器 PDF/图片导出。

### 当前不做

- 完整桌面应用外壳、AI 助手、账号系统、云存储和协作服务。
- 为未知宿主设计插件平台、任意语言原生库接入或多套核心实现。
- 把宏执行、全部历史二进制格式、全部图表和复杂排版特性默认纳入首版。
- 通过浏览器打印、隐藏 Electron 窗口或远程服务，宣称已经实现可移植的核心转换能力。

## 2. 技术选型

| 选择 | 职责与理由 | 边界 |
| --- | --- | --- |
| MoonBit | 实现主要文档算法和模型；作为面向 WASM 的核心开发语言 | 编译速度、性能、包体积和依赖成熟度仍须在真实文档上测量 |
| WasmGC | 浏览器 SDK 默认产物；由运行时管理对象，适合文档树、字符串和公式表达式等数据结构 | 不承诺一定比传统 WASM 快；GC、字符串 builtins 和其他 WASM 特性需要分别验证 |
| TypeScript | Web SDK、浏览器平台接入、绘制执行和必要 UI | 不另建文档引擎，不重复实现核心编辑、布局和格式语义 |
| moonrun | 本地运行核心、测试和 CLI 入口的候选宿主 | 不是浏览器，不自动提供 DOM、CSS 排版、Canvas 或 PDF 输出 |

Rust、Zig、Go 不作为当前核心主语言。选择 MoonBit 不意味着为了“全 MoonBit”重写所有成熟底层库：遇到字体塑形、图像或编解码能力缺口，先评估可复用的 WASM 组件、调用成本及授权，再决定引入或移植；不默认把缺失算法搬到 TS。

### WasmGC 与传统 WASM

- 传统 WASM 主要在线性内存中表示数据，由模块携带分配器、引用计数或 GC；WasmGC 使用运行时管理的结构体、数组和引用。MoonBit 同时提供相应编译目标。
- 浏览器阶段只建立 WasmGC 构建路径。传统 WASM 是 P9 跨宿主遇到已证实的限制时再验证的编译选项，不提前建立双后端维护体系。
- WasmGC 对象不等于普通 JS 对象，也不能直接作为 C 指针使用；字节输入、字符串和批量结果需要明确的边界转换。
- 支持 WasmGC 不等于支持 JS string builtins。是否启用后者，以目标浏览器和后续非浏览器运行时实测为依据。
- 同一份核心源码不等于同一个二进制可在所有宿主直接运行。WASM 特性、imports、导出类型和运行入口必须一起匹配。

### moonrun 的使用边界

当前上游主分支文档描述：交付配置使用 V8，Wasmtime 后端是编译时开发特性，并存在实验性 Rust 嵌入接口。开发时应固定工具链版本，不能把主分支功能等同于已安装版本的能力。

核心不直接调用 moonrun 专属文件、网络或异步接口；这些依赖留在 CLI 入口。依赖 `moonbit_v0` 等宿主 imports 的模块，不会自动兼容浏览器或其他 WASM runtime。moonrun 的权限策略也不等于完整 OS 沙箱。

## 3. 核心与宿主职责

“逻辑尽可能放入 WASM”是状态与算法归属原则，不以语言代码行数占比为目标。“纯计算核心”允许维护文档会话、撤销历史、缓存和增量布局状态，但不直接依赖外部 I/O 或浏览器环境。

| 能力 | WASM / MoonBit | Web / TS 或 CLI 宿主 |
| --- | --- | --- |
| 文件格式 | ZIP/OPC、XML、OOXML 语义、解析与写回、兼容性诊断 | 获取输入字节、保存输出字节 |
| 文档模型 | 文档权威状态、对象标识、样式解析、资源引用 | 只持有句柄及呈现所需快照，不维护第二份可独立编辑的模型 |
| 编辑 | 命令、范围变换、选区语义、撤销重做、格式操作 | 接收平台事件，转换为命令；显示核心返回的状态 |
| 计算 | 公式、依赖更新、表格和图形几何 | 调度请求、展示结果 |
| 排版 | 字体度量、塑形、双向文本、换行、分页、布局及命中测试 | 获取字体资源、提供视口和缩放参数、呈现结果 |
| 渲染 | 生成位置已确定的绘制批次、文本/字形及资源引用 | 调用 Canvas/SVG 等平台绘制接口，不重新决定换行和分页 |
| 输入与 UI | 编辑语义和最终文档变化 | DOM、IME 生命周期、键盘、指针、焦点、剪贴板、无障碍、菜单与面板 |
| 资源 | 资源关系、内容解析，以及逐步纳入的编解码计算 | 字体/图片获取、平台资源对象的创建与释放 |
| 转换 | 格式映射、布局和可移植输出算法；按具体格式逐项实现 | 提供输入资源、收集输出，不隐藏服务端或浏览器依赖 |

特别约束：

- 字体文件、替代字体规则和文本布局结果应具有一致来源。不能让 WASM 用一套度量分页、TS 再用另一套规则重排。
- 若某项能力暂时依赖浏览器度量或平台编解码器，必须标明支持边界；不能据此宣称无浏览器环境等价支持。
- IME、焦点和无障碍仍需要真实平台适配。TS 薄层不等于删除这些能力，也不等于用 MoonBit 包装每个 DOM 调用。
- 不引入 Tiptap、Univer 等第二套编辑模型来临时承担核心语义；如需借鉴它们，提取规则和验证样本，而不是维持双向模型同步作为最终架构。

### 调用边界

- 输入主要是文档字节、资源字节、编辑命令和视口参数；输出主要是布局/绘制结果、必要状态、诊断和保存字节。
- 以文档会话为单位运行，显式释放会话与宿主资源；GC 不代替图片、Worker 等外部资源的生命周期管理。
- 按命令、页面或批次跨边界调用，避免逐字符/逐单元格调用和每次编辑都复制完整文档。
- Worker 间传输使用可序列化数据或字节，不假设 WasmGC 引用可直接跨 Worker 共享。
- 先用实际垂直切片确定最小 API，不预建通用 RPC、插件协议或复杂二进制协议。

## 4. 跨阶段的 SDK 验证目标

先完成一个真实文档的垂直切片，再扩展格式和功能。首个完整格式选择 DOCX，以字体与分页尽早暴露最大风险；P0 纯文本 POC 只验证工程与宿主边界。以下是跨 P2–P9 的验证方向，不是 P1/P2 必须一次完成的功能。阶段范围见[路线图](roadmap.md)。

完成证据应包括：

1. **读写闭环**：解析真实 OOXML 文件，查询与修改内容，保存后在参考应用重新打开；检查未修改内容、未识别 XML/资源和关系是否保留。无法保留的情况给出诊断，不静默丢失。
2. **Web 编辑闭环**：Worker 中加载 WasmGC，预览、输入、选区、撤销、保存均使用同一核心状态；覆盖中文 IME、组合字符、RTL、图片和表格等相关样本。
3. **布局闭环**：固定字体和输入后验证换行、分页与字形位置；证明 TS 绘制层没有补做另一套布局。浏览器画面与非浏览器布局结果分别核验。
4. **P9 跨宿主可行性探针**：同一份核心源码通过 moonrun 完成一次读取、修改和保存；检查 imports，记录入口差异，不据此宣称支持任意运行时。
5. **性能证据**：记录工具链版本、目标浏览器、样本、调试/发布构建时间、WASM 原始及压缩体积、资源体积、首次打开、增量编辑、保存耗时、峰值内存和边界复制成本。
6. **失败路径**：覆盖损坏文档、资源缺失、过大解压内容和不支持特性；限制不可信输入造成的无界资源消耗，不能以空白文档伪装成功。

这些是验证方向，不是当前已通过的测试，也不预设未经测量的毫秒、体积或工期指标。

以下情况应暂停扩大范围并重新评估实现路径，而不是默默把逻辑转移到 TS：

- 关键字体、Unicode、ZIP/XML 库在目标 WasmGC 环境无法满足真实样本。
- 必须依靠 DOM 排版或另一套编辑器模型，才能完成目标功能。
- 边界复制、内存占用或增量更新成本已经阻碍目标文档的可用性。
- 需要不符合项目授权目标的商业组件，或不可接受的浏览器/服务端依赖。
