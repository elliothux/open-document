# SDK 目标、技术选型与核心/宿主合同

**当前目标（2026-10-14）：复刻 GenOffice 的文档、表格、PPT、PDF，交付全功能 SDK。** 本地 `references/genoffice` 源码用于核对功能与 UI 交互，App 仅用于视觉对比验收和交互参考。Office 能力、布局、算法与兼容行为仍优先参考 ONLYOFFICE，其次 LibreOffice。目标覆盖读取、呈现、交互编辑、程序化操作、保存及转换；P0–P9 是已交付的基础阶段，其限定范围不构成最终产品上限。

项目未发布，当前有 0 个用户。现有基础包括 [P0 文本 POC](../implemented/p0-project-foundation.md)、[P1 字体/塑形](../implemented/p1-sdk-foundation.md)、[P2 窄 DOCX 读写](../implemented/p2-format-foundation.md)、[P3 有限预览/PDF](../implemented/p3-docx-preview.md)及 [P4 限定 DOCX 编辑](../implemented/p4-docx-editing.md)。实际 API 与支持面见[开发说明](development.md)和[格式合同](formats.md)。未发布 API、模型和开发数据沿单一实现路径直接修改。

[P5 XLSX](../implemented/p5-xlsx-editing.md)已交付限定网格、值/公式编辑、保存与基础打印。XLSX 沿用本合同与 [R0](../implemented/r0-renderer-foundation.md) 的核心/Renderer 分工，支持边界归格式合同。

[P6 PPTX](../implemented/p6-pptx-editing.md)已交付限定图文、单对象/文本框编辑、保真保存和静态 PDF。MoonBit 拥有主题继承、对象、文本、变换与命中；三种格式共用有序绘制与 PDF 底层。

[P7 PDF 输入](../implemented/p7-pdf-input.md)与 [P8 PDF 文档操作](../implemented/p8-pdf-operations.md)已交付限定读取、源图文、文字查询、页面整理、批注/普通字段和保存。PDF 解析、原始坐标解释、文字查询、对象修改和保存归 MoonBit；Web 复用通用 Renderer 和原生草稿输入，不另建 PDF 引擎。

按当前需求从 Day One 设计。需求可以直接改变最底层架构、模型、接口和数据流；选择合理实现，同步修改调用方、测试和文档，删除被替代的路径。兼容代码仅限文档格式；禁止保留旧接口、内部模型、配置或开发数据的兼容层、迁移垫片、双写和旧实现回退。

本文件拥有当前产品目标、技术选型和核心/宿主合同，参考源码入口见[上游项目](upstream-projects.md)。新增依赖或机制按当前功能缺口确定。

**已确定选型：MoonBit + WasmGC + TypeScript；默认 Web UI 使用 React + Shadow DOM + Tailwind CSS + Base UI（`@base-ui/react`）。文档逻辑尽可能在 WASM 内实现，平台适配与 Renderer 保持薄层。**

功能清单和默认 Web UI 按 GenOffice 源码核对；Office 实现、布局、算法与独立测试基准优先使用 ONLYOFFICE core/sdkjs，其次 LibreOffice。GenOffice 的引擎选型不改变本项目的核心边界。源码入口见[上游项目](upstream-projects.md)，已有证据保留真实来源，执行规则见[测试说明](testing.md)。

当前先交付核心功能：每次完成真实文件的一项操作及所需保存/重开，修复功能和文档完整性问题。完成足够检查后交付可操作入口与输出。资源安全上限、原子拒绝、错误恢复、键盘/焦点语义及执行超时贯穿各优先级；核心功能阶段遇到卡死或持续不可交互时做最小诊断。性能专项属于功能优先级 P1。

## 1. 产品目标与优先级

“全功能”以 GenOffice 四类编辑器实际实现的文档能力为清单，不等同于无限制的 Microsoft Office 或 PDF 标准兼容。每项能力分别跟踪读取、显示、编辑、保存、程序化 API 和默认 UI；占位入口、只读保留或仅有内部实现不能记为 SDK 完成。平台依赖的功能列为待移植或宿主适配，不从差距清单中消失。桌面外壳、账号和云服务不随编辑器功能自动纳入 SDK，AI 服务与外部集成单列边界。

| 功能优先级 | 交付重点 | 边界 |
| --- | --- | --- |
| P0 核心功能 | 四类编辑器的主要操作、默认 UI、程序化 API、保存和常用输出 | 新增功能同时完成必要的布局、格式读写与风险检查；不能把基本可用性推迟到 P1 |
| P1 兼容与性能 | 扩大真实文件、格式变体、复杂排版、公式与效果覆盖，改善大文件交互和资源占用 | 基于功能差距和实测瓶颈优化，不先建性能平台或扩大浏览器矩阵 |
| P2 次要与外围能力 | AI 集成、协作、Diff、外部服务及次要平台接入 | 保留在完整目标中，独立于 P0/P1 交付；本地批注和修订编辑属于 P0 |

“功能优先级 P0/P1/P2”与“阶段 P0–P16”是两套标记。已完成阶段保留编号，待实现阶段按实施顺序编号；阶段顺序和任务归属只在[路线图](roadmap.md)维护。逐项差距见 [G3 功能对照](../g3-genoffice-sdk-gap.md)。

### 首要平台：WASM + Web 浏览器

当前浏览器支持范围只包含 Chrome/Chromium。浏览器兼容、自动化、输入及性能验收均使用 Chrome 内核；不维护其他浏览器引擎的适配或测试矩阵。执行规则见[测试说明](testing.md)。

- 提供可嵌入现有 Web 应用的开发者 SDK，而不是完整桌面 Office 应用。
- 面向 DOCX、XLSX、PPTX、PDF，覆盖预览、交互编辑、程序化读写及按方向定义的格式转换。
- 浏览器本地运行文档核心；基础能力不以远程转换服务、Electron 或商业 Office 服务为前提。
- 同一核心拥有解析、模型、编辑语义、计算、布局和序列化能力；Web 侧提供类型明确的 TS API 和必要视图。
- 导入、导出、布局及编辑能力分别声明支持范围。不能把“能读取”“能展示”“能无损写回”和“能编辑”混为同一兼容性承诺。
- 长耗时计算以 Worker 承载为默认实现方向，避免阻塞输入与页面交互。

首版不同时承诺四种格式的完整兼容。平台顺序仍是 Web 优先，CLI 与其他宿主后续接入；各格式和转换方向按功能清单推进，不承诺任意格式互转或与 Microsoft Office 完全一致。

### 次要平台：其他语言 + WASM runtime，以及 CLI

- 复用 MoonBit 核心，提供无浏览器环境的程序化读写、计算及逐步完善的转换能力。
- CLI 是其他语言接入的第一条简单路径；随后验证一个明确的 WASM runtime 和语言绑定，再按实际需求扩展。
- moonrun 用作开发、测试和首个 CLI 宿主的候选，不成为文档核心的依赖。
- 不要求各语言通过 FFI 加载原生动态库，不在浏览器优先阶段建设 native ABI、多语言 binding 生成器或通用运行时框架。
- 数据操作跨平台与视觉输出跨平台分别验收。CLI 能启动、能修改文件，不代表已支持无浏览器 PDF/图片导出。

### 后续与范围边界

- AI、协作和 Diff 按功能优先级 P2 安排。SDK 提供可替换的接入能力，账号、云存储和服务运营由宿主承担。
- 不复刻完整桌面应用外壳，不把 Electron、操作系统菜单或文件关联当成 Web SDK 必需能力。
- 只为已确定的宿主提供接入，保持同一核心，不预建未知宿主的插件平台或任意语言原生库。
- 首版按具体功能清单交付；宏执行、全部历史二进制格式及全部复杂特性不默认纳入。
- 核心转换按实际依赖声明可移植范围；浏览器打印、Electron 或远程服务的结果不算无宿主依赖的核心输出。

## 2. 技术选型

| 选择 | 职责与理由 | 边界 |
| --- | --- | --- |
| MoonBit | 实现主要文档算法和模型；作为面向 WASM 的核心开发语言 | 编译速度、性能、包体积和依赖成熟度仍须在真实文档上测量 |
| WasmGC | 浏览器 SDK 默认产物；由运行时管理对象，适合文档树、字符串和公式表达式等数据结构 | 不承诺一定比传统 WASM 快；GC、字符串 builtins 和其他 WASM 特性需要分别验证 |
| TypeScript | Web SDK、浏览器平台接入、绘制执行和必要 UI | 不另建文档引擎，不重复实现核心编辑、布局和格式语义 |
| moonrun | 本地运行核心、测试和 CLI 入口的候选宿主 | 不是浏览器，不自动提供 DOM、CSS 排版、Canvas 或 PDF 输出 |

Rust、Zig、Go 不作为当前核心主语言。选择 MoonBit 不意味着为了“全 MoonBit”重写所有成熟底层库：遇到字体塑形、图像或编解码能力缺口，先评估可复用的 WASM 组件、调用成本及授权，再决定引入或移植；不默认把缺失算法搬到 TS。

### 默认 Web UI：现有能力已接入

各领域的 `react` 入口使用 React + open Shadow DOM + Tailwind CSS + [Base UI](https://base-ui.com/react/overview/quick-start)，接通本格式已有操作。`packages/ui` 提供共用外壳和控件；领域的 `web` 入口保持框架无关。`packages/web-core` 复用连接、原生输入、Renderer、Canvas 和快照，领域宿主保留各自的编辑队列。

交付与检查边界见 [P9](../implemented/p9-web-sdk-ui.md)。挂载、状态、保存/关闭与资源所有权归[格式合同](formats.md#默认-ui-与编辑宿主)，实际入口与普通 JS 示例归[开发说明](development.md#默认-web-ui)。新建和缺失格式操作继续按 P10–P13 实施。

| 层 | 职责 |
| --- | --- |
| React | 工具栏、菜单、侧栏、状态栏和对话框；管理界面状态，展示核心返回的状态 |
| Shadow DOM | 每个编辑器实例一个 open ShadowRoot，容纳 UI、编辑表面、样式与弹层 |
| Tailwind CSS | 构建期生成 UI 样式，按 GenOffice 的颜色、间距、尺寸和状态实现外观 |
| Base UI | 提供菜单、弹层、选择器等控件的交互与无障碍基础，由 Tailwind 定义外观 |

UI 与交互以 `references/genoffice` 源码为第一参考。GenOffice App 仅用于视觉对比验收和交互参考；出现差异时先检查源码与 App 的版本。复刻编辑区域布局、Ribbon 分组、控件状态、菜单与面板行为、状态栏和缩放操作。首批接通现有核心支持的操作；缺少的文档能力按具体用户操作补齐，不用空按钮宣称功能完成。这里的 UI 参考不改变 Office 布局与算法的参考顺序。桌面外壳、AI、账号与云服务沿用本合同的范围边界。

实现遵守以下边界：

- 默认 UI 通过框架无关的 Web SDK 调用会话与命令。宿主可用普通 JS 挂载，也可替换 UI；核心、Worker 通信和 Renderer 不依赖 React。
- 文档权威状态、编辑语义、历史、布局与序列化继续归 MoonBit。GenOffice 中依赖 Tiptap、Univer 或 Electron 的调用改接本项目接口，不引入第二套编辑模型。
- Canvas、原生输入和无障碍语义节点保持稳定。React 更新 UI 状态，不因工具栏或面板变化重建编辑表面；保留输入法、选区、保存与释放流程。
- Tailwind 产物与基础样式放入 ShadowRoot，主题变量在 `:host` 或实例容器定义；不要求宿主安装 Tailwind。UI 主题不改变文档颜色，UI 尺寸不改变文档缩放。
- Base UI 的 Portal 明确指定实例内弹层容器。焦点查询、外部点击判断和键盘处理按实际 ShadowRoot 工作；菜单关闭后恢复相应焦点与编辑选区。Portal 容器可配置不等于全部交互已验证。
- 按实际使用的控件引入依赖，在接入时固定版本并更新依赖记录。复用 GenOffice 源码或资源时保留对应许可与来源。

检查只覆盖本次接入的真实操作：在 Chromium 中确认宿主与编辑器样式隔离、菜单/弹层的键盘与焦点、原生输入和相关命令结果。涉及保存或生命周期时延伸已有保存重开与释放用例。颜色、间距和布局按源码实现后，对照 GenOffice App 直接审阅，不另建截图矩阵、全组件验收或性能专项。

### WasmGC 与传统 WASM

- 传统 WASM 主要在线性内存中表示数据，由模块携带分配器、引用计数或 GC；WasmGC 使用运行时管理的结构体、数组和引用。MoonBit 同时提供相应编译目标。
- 浏览器阶段只建立 WasmGC 构建路径。传统 WASM 是 P16 跨宿主遇到已证实的限制时再验证的编译选项，不提前建立双后端维护体系。
- WasmGC 对象不等于普通 JS 对象，也不能直接作为 C 指针使用；字节输入、字符串和批量结果需要明确的边界转换。
- 支持 WasmGC 不等于支持 JS string builtins。是否启用后者，以目标浏览器和后续非浏览器运行时实测为依据。
- 同一份核心源码不等于同一个二进制可在所有宿主直接运行。WASM 特性、imports、导出类型和运行入口必须一起匹配。

### moonrun 的使用边界

当前上游主分支文档描述：交付配置使用 V8，Wasmtime 后端是编译时开发特性，并存在实验性 Rust 嵌入接口。开发时应固定工具链版本，不能把主分支功能等同于已安装版本的能力。

核心不直接调用 moonrun 专属文件、网络或异步接口；这些依赖留在 CLI 入口。依赖 `moonbit_v0` 等宿主 imports 的模块，不会自动兼容浏览器或其他 WASM runtime。moonrun 的权限策略也不等于完整 OS 沙箱。

## 3. 核心与宿主职责

“逻辑尽可能放入 WASM”是状态与算法归属原则，不以语言代码行数占比为目标。“纯计算核心”允许维护文档会话、撤销历史、缓存和增量布局状态，但不直接依赖外部 I/O 或浏览器环境。

| 能力 | WASM / MoonBit | Web / TS 或 CLI 宿主 |
| --- | --- | --- |
| 文件格式 | ZIP/OPC、XML、OOXML 语义、解析与写回、兼容性诊断 | 获取输入字节、保存输出字节 |
| 文档模型 | 文档权威状态、对象标识、样式解析、资源引用 | 只持有句柄及呈现所需快照，不维护第二份可独立编辑的模型 |
| 编辑 | 命令、范围变换、选区语义、撤销重做、格式操作 | 接收平台事件，转换为命令；显示核心返回的状态 |
| 计算 | 公式、依赖更新、表格和图形几何 | 调度请求、展示结果 |
| 排版 | 字体度量、塑形、双向文本、换行、分页、布局及命中测试 | 获取字体资源、提供视口和缩放参数、呈现结果 |
| 渲染 | 生成位置已确定的绘制批次、文本/字形及资源引用 | 调用 Canvas/SVG 等平台绘制接口，不重新决定换行和分页 |
| 输入与 UI | 编辑语义和最终文档变化 | DOM、IME 生命周期、键盘、指针、焦点、剪贴板、无障碍、菜单与面板 |
| 资源 | 资源关系、内容解析，以及逐步纳入的编解码计算 | 字体/图片获取、平台资源对象的创建与释放 |
| 转换 | 格式映射、布局和可移植输出算法；按具体格式逐项实现 | 提供输入资源、收集输出，不隐藏服务端或浏览器依赖 |

特别约束：

- 字体文件、替代字体规则和文本布局结果应具有一致来源。不能让 WASM 用一套度量分页、TS 再用另一套规则重排。
- 若某项能力暂时依赖浏览器度量或平台编解码器，必须标明支持边界；不能据此宣称无浏览器环境等价支持。
- IME、焦点和无障碍仍需要真实平台适配。TS 薄层不等于删除这些能力，也不等于用 MoonBit 包装每个 DOM 调用。
- 不引入 Tiptap、Univer 等第二套编辑模型来临时承担核心语义；如需借鉴它们，提取规则和验证样本，而不是维持双向模型同步作为最终架构。

[R0 通用渲染架构](../implemented/r0-renderer-foundation.md)细化本节的绘制职责，统一各格式核心与平台 Renderer 的数据、资源和更新设计。DOCX、XLSX、PPTX 与 PDF 已接入 Web，后续格式与宿主沿用同一合同。

[R1 领域拆包与共享 Wasm 加载](../implemented/r1-domain-packages-shared-wasm.md)提供四格式的 `core`、`web`、`react`、`worker` 入口，继续共用一个 Wasm 产物。公共 Loader 按绝对 URL 与构建身份复用获取/编译结果；每文档独立创建 Instance、Worker 和资源集合。公共前端层不反向导入领域包，React 入口由宿主按需加载。当前产物仍包含全格式核心，不代表已分发单格式 Wasm。

### 调用边界

- 输入主要是文档字节、资源字节、编辑命令和视口参数；输出主要是布局/绘制结果、必要状态、诊断和保存字节。
- 以文档会话为单位运行，显式释放会话与宿主资源；GC 不代替图片、Worker 等外部资源的生命周期管理。
- 按命令、页面或批次跨边界调用，避免逐字符/逐单元格调用和每次编辑都复制完整文档。
- Worker 间传输使用可序列化数据或字节，不假设 WasmGC 引用可直接跨 Worker 共享。
- 先用实际垂直切片确定最小 API，不预建通用 RPC、插件协议或复杂二进制协议。

## 4. 跨阶段的 SDK 验证目标

每次完成一个真实文档的垂直切片，再扩展功能与兼容面。阶段 P0 的纯文本 POC 只验证了工程与宿主边界，P3–P8 已完成各自声明的有限能力。以下是持续采用的验证方向，不是一次性验收清单。阶段范围见[路线图](roadmap.md)。

按当前功能从下列证据中选择，完成足够检查后交付；新变更或未解决问题需要时再扩展：

1. **读写闭环**：解析真实 OOXML 文件，查询与修改内容，保存后在参考应用重新打开；检查未修改内容、未识别 XML/资源和关系是否保留。无法保留的情况给出诊断，不静默丢失。
2. **Web 编辑闭环**：Worker 中加载 WasmGC，预览、输入、选区、撤销、保存均使用同一核心状态；覆盖中文 IME、组合字符、RTL、图片和表格等相关样本。
3. **布局闭环**：固定字体和输入后验证换行、分页与字形位置；证明 TS 绘制层没有补做另一套布局。浏览器画面与非浏览器布局结果分别核验。
4. **P16 跨宿主可行性探针**：同一份核心源码通过 moonrun 完成一次读取、修改和保存；检查 imports，记录入口差异，不据此宣称支持任意运行时。
5. **资源安全**：保留有界输入、失败恢复和释放检查。专项性能测量延后，只有实际卡死、无法交互或资源失控才最小诊断。
6. **失败路径**：覆盖损坏文档、资源缺失、过大解压内容和不支持特性；限制不可信输入造成的无界资源消耗，不能以空白文档伪装成功。

这些是验证方向，不是当前已通过的测试，也不预设未经测量的毫秒、体积或工期指标。

以下情况应暂停扩大范围并重新评估实现路径，而不是默默把逻辑转移到 TS：

- 关键字体、Unicode、ZIP/XML 库在目标 WasmGC 环境无法满足真实样本。
- 必须依靠 DOM 排版或另一套编辑器模型，才能完成目标功能。
- 边界复制、内存占用或增量更新成本已经阻碍目标文档的可用性。
- 需要不符合项目授权目标的商业组件，或不可接受的浏览器/服务端依赖。
