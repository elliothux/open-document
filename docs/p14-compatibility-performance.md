# P14 兼容与性能

状态：`planned`。首轮测试素材、运行环境和当前行为基线已准备；下一步实施 P14.1。

用户结果：P10–P13 的打开、编辑、撤销、保存和输出操作能用于更多真实文件，指定的复杂文件和大文件操作达到可用。Office 行为优先对齐 ONLYOFFICE，其次 LibreOffice。

## 交付范围

按功能族分批交付。每批确定输入、操作、预期和支持边界，把读取、编辑、历史、保存重开及必要输出一起完成。新增缺口进入后续批次，性能按具体慢操作单独改进。

复用现有 SDK、默认 UI 和 Renderer。失败事务保留文档与历史；未改动内容保持完整。旧格式、加密和更广效果逐项扩展，OCR、证书及跨宿主归后续阶段。接口与支持边界沿用 [SDK 合同](references/sdk.md)和[格式合同](references/formats.md)。

## 首批 XLSX 验收

使用四份原件，保留清单中的全部预期。

| 输入 | 操作与关键预期 |
| --- | --- |
| `Shared_formulas.xlsx` | A1 改为 2，核对全部目标单元格的有效公式和值；其中 A6 的公式为 `A5+1`、值为 7 |
| `RangesReferencesOverDeletedRows.xlsx` | 删除 8:13 行，C1 从 `SUM(F14:G14)` 变为 `SUM(F8:G8)`，值仍为 2 |
| `basic.xlsx` | 修改 A2 再恢复，使依赖失效；实际重算 B2:B19 为 10…180 |
| `refupdate.xlsx` | 删除第 5 行，B1:E1 为 `B29+1`…`E29+1`，值均为 2 |

单元格修改使用原生公式输入，删行先用公开 SDK 结构命令验证。每案检查撤销/重做、独立输出 XML、未改部件和保存重开；受影响的默认 UI 操作补对应回归。

先定位阻塞原件操作的布局、错误状态及工作簿扩展/视图边界，再修公式与引用规则。保留原件和既有保护，按确认的格式语义扩展支持。

## 实现职责

XLSX 公式展开、依赖重算和引用更新归 `modules/formats/src/xlsx`。DOCX/PPTX 读写归对应格式模块，分页与文字几何归 `modules/layout`。PDF 解析、对象与保存沿用现有 PDF 核心。

Worker、输入、传输和 Canvas 调度归各领域 Web 包及 `packages/web-core`。共享规则在所属核心修改，公开 API 和默认 UI 仅补本批需要的操作。

## 验证与性能

每批使用原件及独立预期验证读取、实际编辑或重算、保存、重开和必要渲染。数值、错误类型、源结构和布局分别判断；缓存正确或源内容保留不能代替编辑能力。

视觉检查先确认文字、页数、对象与关键几何，再比较目标区域像素。容差依据字体、单位及测量误差预先确定。

性能复用现有测量工具，每次固定一个输入和操作，区分冷/热、核心、Worker 往返、绘制及输入反馈耗时。先确认输出正确且可比，再重复采样比较；阈值依据同环境基线与实际可用性问题确定。未测量的内存峰值保留为未测。

每批所选正向用例、保护用例和受影响回归通过后，更新支持范围及剩余差距，再将该批标为 `implemented`。测试范围与证据规则沿用[测试说明](references/testing.md)。
