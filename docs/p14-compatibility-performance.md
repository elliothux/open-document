# P14 兼容与性能

状态：`planned`。首轮测试素材和行为基线已入库；下一步实施 P14.1。以下验收随各批次实现，素材检查通过不代表功能验收完成。

用户结果：P10–P13 的打开、编辑、撤销、保存和输出操作能用于更多真实文件，指定的复杂文件和大文件操作达到可用。Office 行为优先对齐 ONLYOFFICE，其次 LibreOffice。

## 交付范围

按功能族分批交付。每批确定输入、操作、预期和支持边界，把读取、编辑、历史、保存重开及必要输出一起完成。新增缺口进入后续批次，性能按具体慢操作单独改进。

复用现有 SDK、默认 UI 和 Renderer。失败事务保留文档与历史；未改动内容保持完整。旧格式、加密和更广效果逐项扩展，OCR、证书及跨宿主归后续阶段。接口与支持边界沿用 [SDK 合同](references/sdk.md)和[格式合同](references/formats.md)。

## 各批次验收

### 共同通过条件

每个功能批次都完成以下检查；具体输入、编辑目标和预期见后面的分批合同。

1. 打开原件，核对本批涉及的全部文字、对象、公式或图像。无编辑保存满足现有源保留合同。
2. 通过公开 SDK 和受影响的默认 UI 执行指定操作。撤销恢复修改前的内容与原字节，重做恢复修改后内容；失败操作不改变文档、revision 或历史。
3. 保存后，用独立工具检查原生结构与结果，并由新 SDK 会话重开、继续操作。未修改的部件、关系和资源保持完整；合法变化的关联元数据按实际引用核对。
4. 布局相关批次检查实际 Canvas 和导出 PDF，按文字、对象、页数、关键几何和目标像素分别判断。先冻结原件及指定编辑状态的独立参考、字体、引擎和容差；缺参考时保留待验收，整批保持 `planned`。

必选正向案例、保护案例和直接受影响回归全部通过，才完成对应功能批次。运行命令和详细结果仍由私有测试库维护。

### P14.P1 性能

每次只验收一个已复现的慢操作，选中输入及相邻回归在优化前固定。

| 格式 | 选中操作 | 正确性检查 |
| --- | --- | --- |
| DOCX | 导入保存、首次/重复布局、首部/尾部编辑或 PDF 导出，复用现有输入 | 全文、页数、行位置、选区、历史和输出结构正确；布局计数用于定位工作量 |
| XLSX | 单格修改后的依赖重算、指定删行或保存 | 全部受影响公式和值、未改单元格、历史和保存重开正确 |
| PPTX | 指定复杂页切换、文本框编辑后的重绘或保存 | 对象数量、文字、布局、命中、历史和输出保持正确 |
| PDF | 首次显示、指定翻页/搜索或多页图片输出 | 页序、文字/搜索结果、目标像素及输出文件正确 |

1. 固定优化前后两个构建、输入、字体、机器和 Chromium。核心耗时、Worker 往返、绘制及输入到可见反馈分开测量；加载/初始化与已就绪操作分开记录。
2. 复用现有串行采样：每侧 5 次预热、20 对 A/A 校准，再冻结噪声与回退预算，交替 AB/BA 采集 20 对 A/B。独立正确性检查在计时间隔外执行。
3. 目标和相关操作的 A/A 校准均须可靠。目标操作的中位耗时降幅超过已冻结的 `noiseMs`，相关操作判定为 `within-budget`，才判该项提速；噪声不可靠或差异未超过噪声则保留不确定。只做相同产物对照或只报 P95，不能完成优化验收。
4. 输入反馈优化还须证明原生输入到可见结果的改善。取消、关闭和重开后不得遗留 Worker、任务或 Blob URL；超预算输入按合同拒绝并能恢复。JS heap、RSS 和 WasmGC 峰值分别记录，未测峰值保持未测。

旧结果错误时，先完成正确性修复，再建立可比基线。现有性能脚本的完整资格前置条件继续有效；通过选中兼容案例不能替代该条件。

## 实现职责

XLSX 公式展开、依赖重算和引用更新归 `modules/formats/src/xlsx`。DOCX/PPTX 读写归对应格式模块，分页与文字几何归 `modules/layout`。PDF 解析、对象与保存沿用现有 PDF 核心。

Worker、输入、传输和 Canvas 调度归各领域 Web 包及 `packages/web-core`。共享规则在所属核心修改，公开 API 和默认 UI 仅补本批需要的操作。
