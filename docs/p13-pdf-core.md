# P13 PDF 核心功能

状态：`planned`。2026-10-28 根据已完成的 P10–P12 和 R1 拆包细化；本文不表示新增能力已经实现。

用户可以新建和整理 PDF，编辑受支持的文字与图片，完成批注、表单、真实脱敏及常用输出。文本型 PDF 可以转换为可编辑的 DOCX、XLSX、PPTX。范围对应 [G3 PDF](g3-genoffice-sdk-gap.md#pdf) 的 P0 项。复杂格式兼容归 P14，OCR、证书签名、AI 和协作归 P15。

沿用 [SDK 合同](references/sdk.md)、[R0 渲染架构](implemented/r0-renderer-foundation.md)和 [R1 领域拆包](implemented/r1-domain-packages-shared-wasm.md)。GenOffice 定义功能与交互；Office 算法、对象和写回行为优先参考 ONLYOFFICE，其次 LibreOffice。默认 UI 继续使用 React、open Shadow DOM、Tailwind 和 `@base-ui/react`。

## 当前基础与交付顺序

[P7](implemented/p7-pdf-input.md) 已有严格读取、有限图文预览和文字查询。[P8](implemented/p8-pdf-operations.md) 已有重排、旋转、删除、便笺、高亮、部分表单填写及源对象保存。[P9](implemented/p9-web-sdk-ui.md) 已接入打开、替换、保存、另存和释放；[浏览器打印](references/formats.md#浏览器打印)也已实现。P13 扩展这些路径。

当前 [`PdfSession` 页面视图](../modules/formats/src/pdf/input-session.mbt)只保留一个 `PageDisplay`，渲染下一页会释放上一页资源并重置选区。`TextSpan.source` 用于显示来源，尚不是可写的内容流定位。[普通保存](../modules/formats/src/pdf/input-edit.mbt)重建 xref，但保留未引用对象。三处限制分别影响多页阅读、正文编辑和脱敏，必须在核心解决。

| 批次 | 最低完整交付 | G3 对应 |
| --- | --- | --- |
| 1 创建与阅读 | 空白 PDF；连续/单页/双页阅读、缩略图、大纲、链接、跨页选择和搜索导航；常用元数据 | F01、F02、F21 |
| 2 页面与文件整理 | 空白页、插入/替换/提取、合并文件、拆文件；裁剪、尺寸、拆页和多页合一 | F03–F05 |
| 3 正文与叠加内容 | 文字、图片插入/修改/删除；位置与样式；批量水印、页码、页眉页脚 | F06、F07、F12 |
| 4 批注与表单 | 标记、绘图、回复、印章/签名外观；常用字段填写与设计 | F08–F11、F13、F14 |
| 5 真实脱敏 | 区域预览、内容移除、独立清理输出、不可安全处理时拒绝 | F15 |
| 6 输出与转换 | PNG/JPEG、HTML/Markdown；分别交付 PDF → DOCX/XLSX/PPTX | F19、F20 |

每批接通核心、同步/Worker API、默认 UI、保存或输出后交付。第 5 批依赖第 2–4 批的对象定位、资源和外观处理；第 6 批复用第 3 批的提取，并依赖 P10–P12 的目标创建。可以先交付一个转换方向，但三个方向完成前不标记 P13 完成。

## 共同事务与接口约定

以下是待实现的操作合同，具体命令随各批进入 `PdfCommand`；当前接口仍以[格式合同](references/formats.md#pdf-输入与文档操作)为准。

- 沿用稳定页/字段/批注身份、单调 `revision`、候选提交和有界历史。UI 传身份，不把可变页号当身份。
- 修改源前检查修订、保护、字体和资源。一次页面导入、批量叠加或字段设计形成一项历史；失败不改源、选择和历史。
- 内容与资源在同一事务提交。普通保存保留未改字典和流，全部撤销继续返回原字节；新建文件具有自己的初始保存基线。
- 查询分别返回可执行操作及原因。可预览、可复制、可编辑、可转换、可脱敏分别判断；预览完整不能自动授予后四种能力。
- 延续输入草稿、组合输入、拖动、输出和关闭屏障。成功提交后若绘制失败，保留已提交源，允许保存、刷新或显式撤销。
- 输出绑定已提交修订。转换、提取、拆分和脱敏副本不清除原文件未保存状态；只有原格式保存按现有回调结果确认保存。

## 第 1 批：创建、阅读与元数据

### 新建和文件生命周期

由 PDF 核心创建合法页树、资源和空内容流，默认一页，支持明确的页面尺寸。复用底层对象 writer；不把 Office 排版结果绕一圈作为空白 PDF。

`packages/pdf/src/react/file.ts` 接通已有空白文档输入和候选替换。`index.tsx` 开启新建并暴露领域 `create()`；沿用其他格式已完成的新建、未保存确认和失败恢复流程。共用类型 `OfficeDocument` 已包含空白输入，直接复用。

读取并编辑标题、作者、主题、关键词等常用元数据。普通保存同步已有 Info/XMP 的对应字段，保留无关项；无法安全解析的元数据明确限制对应编辑，不能制造两个互相冲突的值。

### 多页资源与阅读操作

把 `PdfSession` 的单页显示槽改为有界的页面视图集合。每项绑定文档修订、页身份、字体资源版本和 `layoutId`，拥有自己的字形、图片及文本索引。页面渲染与当前页/选区切换分开；后台缩略图和输出不改变用户选择。

提供显式释放页面视图的操作。命中、图片解码回传和选择都校验对应视图；内容或字体变化使旧视图失效。P0 可以按修订整体失效；局部失效优化留到出现实际阻塞或 P14。

Web 只保留可见页及小量相邻页的 Canvas。缩略图低分辨率按需生成，离开窗口后释放核心视图，位图受数量和总字节限制。每次调度先完成用户输入和可见页，再处理缩略图；搜索在页边界让出队列。多页和缩略图复用现有 `PdfCanvas`/`CanvasRenderer`，不增加 PDF 专用图元解释器。

核心派生跨页选区、复制顺序和搜索结果；Web 管理滚动、可见范围与页面容器偏移。文字复制继续拒绝未知映射，跨页选择不等于跨页正文编辑。保留原生文本输入、键盘焦点和可访问文本，缩略图/搜索结果提供名称及当前位置。

大纲和链接先支持常见内部页目标、命名目标及普通 URI。核心返回目标与保护原因；宿主仅在用户激活时按既有链接策略处理外链。JavaScript、Launch、OpenAction、外部 stream 不执行。大纲读取不扩张为任意书签、图层和附件管理。

## 第 2 批：页面、几何与跨文件对象

### 页面对象复制

在 PDF 包内实现一次有界对象导入。用“来源文档 + 对象号/代数 → 目标对象”映射复制所选页可达资源，保留同一次导入内的共享关系。展开页树继承值，分配新对象号，修正 `Parent`、页树计数、批注 `/P`、widget/字段关系和受支持的内部目标。

插入与文件合并共用导入；替换由同一候选中的删除和导入完成。提取/拆文件创建新页树，仅带入所选页及必要资源，返回有序命名输出集合。它们是页面组织操作，不能宣称已脱敏。

字段重名按确定规则重命名独立导入字段，不把同名字段意外合并。目标落在未导入页、被替换页或删除页时，先返回关联原因；受支持链接可由用户明确移除，其他无法维护的关系拒绝。普通页标签、直接/命名页目标及常用字段树随操作更新；结构树、文章线程和未知关联不能证明安全时保护相关操作。

### 裁剪、尺寸和拼拆页

API 区分修改页面框与缩放内容。裁剪修改页面框，保留被裁内容；尺寸操作明确锚点及是否缩放。核心统一计算 `MediaBox`、`CropBox`、`Rotate`、`UserUnit` 与显示坐标变换。内容、批注矩形/quad、widget、链接目标一起变换，Web 不复制 PDF 坐标算法。

拆页按选定矩形生成页面；多页合一把来源页的内容资源作为 Form 放置到目标纸张。复用上一节导入和变换，保留可支持的链接/批注。跨边界交互字段或复杂关联无法正确分配时拒绝，不静默丢弃。裁剪、拆页和 Form 裁剪均不移除隐藏源数据。

导入前检查输入总量、对象数、页数和候选预算，导入中继续计费。超过现有单次事务或历史上限时整体拒绝；需要扩大时依据实际核心用例调整，不能绕开限制或留下半份文件。

## 第 3 批：正文、图片与批量叠加

### 可写对象定位

在现有内容解释路径记录可写来源：页身份、内容流对象、Form 调用路径、操作符区间和有效图形/文字状态。相同 XObject 的不同出现位置拥有不同目标。返回绑定修订的对象身份、几何、样式和不可编辑原因；不公开要求调用者拼装内容流位置的协议。

保留原始 token 范围及操作符边界，只重写目标片段。文字状态、字距、矩阵、裁剪和 marked content 的影响都要可确定。多个流或 Form 之间无法隔离的目标保持保护，不能靠预览坐标猜字符串位置。

共享内容流、字体、图片和 Form 在修改某次出现前按需复制，再重绑该路径。其余出现保持原样。资源重命名与引用修改在同一候选完成，不先改共享资源再补救其他页面。

### 文字操作

最低范围是已知字体/编码、可定位的横排文字对象：修改文字、字号/颜色/字体、移动和删除，以及在指定页面插入文字框。保留原对象之外的源位置；局部换行只在用户指定的文字框内进行，不承诺将任意 PDF 页面恢复成可流式重排的 Word 段落。

复用核心字体配置、塑形、嵌入许可检查和子集写出。只有源编码可证明覆盖新文字时才复用编码；否则创建新字体资源并生成 widths、CID 映射和 ToUnicode。缺字或禁止嵌入时要求可用字体，不能用近似 Unicode 或轮廓覆盖伪装成成功编辑。

处理替换导致的文字 advance 变化，保留后续未改文字的明确定位。受影响 `ActualText`、marked content 和相关结构必须同步或拒绝，不能显示新字却复制出旧字。新插入和替换文字沿核心布局生成同一绘制与保存结果。

Web 使用现有原生输入处理组合、粘贴、取消及提交。核心给出光标、选区、对象边框和候选几何；React 不用 DOM 测量决定正文位置。一次确认替换形成一项历史，拖动期间只显示可取消候选。

### 图片与叠加内容

支持现有可解码图片的插入、替换、删除、移动、缩放和旋转。核心维护矩阵、尺寸、颜色空间、mask 与资源关系。裁剪明确是外观裁剪；普通删除仍可能保留源数据。宿主可按现有路径解码 JPEG/输入图片，核心校验尺寸和载荷；不建立第二个图片状态模型。

水印、页眉页脚和页码共用文字/图片创建，支持页范围、位置、样式与前后层次。每次批量操作一次提交；本 SDK 创建的叠加对象可定位、修改和删除。普通导入文字不靠外观猜成水印，页码按本次选定页序生成，重排后由明确操作更新。

## 第 4 批：批注、回复与表单

批注补齐下划线、删除线、墨迹、矩形、椭圆、线/箭头和图片印章；扩展已有高亮/便笺。统一提供创建、属性修改、移动/缩放和删除，支持颜色、边框、透明度、作者和内容。核心生成原生字典与 `/AP` 外观，保存重开与 Canvas 共用几何。

便笺回复维护 `/IRT`、回复类型、Popup 和父子关联。删除线程要明确范围，不能留下悬空引用。手写签名使用 Ink，图片签名/印章使用 Stamp 外观；它们没有密码学签署或验证含义。永久资产库不在本批。

表单以 AcroForm 为范围，补单选组、下拉及列表字段，扩展文本字段与复选框的设计。支持名称、提示、默认值/当前值、只读/必填、文本长度/多行、选项和值以及 widget 位置/尺寸/样式。无交互字段的静态表单通过新增文字或签名外观填写，不能标成可交互字段。

创建、复制、删除和重命名时同步字段树、`Kids/Parent`、页面 `Annots`、`V/DV`、`AS` 和各 widget 的外观。单选按真实导出值工作，选项显示名与保存值分开。多 widget 的一次填写全部成功才提交；新建可编辑文本使用已授权嵌入字体，不依赖阅读器猜测外观。

保留已有签名/认证、未知字段动作和资源保护。XFA、脚本计算/校验、签名字段签署和复杂表单变体分别按 P14/P15 推进；不执行脚本来补表单功能。UI 使用领域属性面板与原生控件，保留标签、键盘及聚焦后的草稿屏障。

## 第 5 批：真实脱敏

### 操作与保存语义

提供“标记区域 → 查看实际移除范围 → 应用并导出脱敏副本”。待应用区域是绑定修订的候选；核心计算实际影响。标记或黑色覆盖不是完成脱敏，普通保存不能报告脱敏成功。

核心新增专门的清理输出路径，返回来源修订、字节和损失说明。源文件及其历史保持可恢复，副本不携带这些数据；用户打开副本时走既有候选替换流程。UI 明示原文件仍含原内容，脱敏导出不调用原文件的 `markSaved`。这样无需改写普通历史语义，也不会让普通保存偶然带入旧对象。

### 最低安全范围

先覆盖可完整解释的页面内容、直接文字、基础路径及私有可解码图片。实际移除按可证明的单位处理：文字至少移除整个受影响字形 cluster；无法安全切分的对象可整体移除，并在应用前展示扩大范围。图片局部处理必须改写像素、mask 和编码数据；不能仅添加裁剪或矩形。

遇到复用图片、含图片的复杂 Form、相交 widget 或无法解析的图形状态，P0 先原子拒绝。后续只有能同时证明清除选区数据和保留其他出现时才开放。签名、加密及现有只读原因仍生效。所有区域先检查，通过后才产生输出。

清理输出必须满足以下条件：

1. 从允许的存活内容重建流和资源引用，不复制含已删 token、注释、填充数据或旧文本替代项的原流。
2. 处理 `ActualText`、替代文本、不可见文字、批注内容/外观和字段值。字体映射与子集只保留存活内容需要的数据，不能残留已删 cluster 的替代文字。未知承载方式不能证明清理时拒绝；受支持的非视觉结构按明确的清理规则移除。
3. 只写清理后的可达对象，移除未用资源、旧内容流、增量修订和原文件载荷。重建 xref/trailer，不走 `stateId == 0` 返回原字节的分支。
4. 脱敏副本默认移除元数据、附件和其他可能保存副本的非必要载荷，并返回清理说明。无法安全遍历时拒绝；普通保存仍保留这些源结构。
5. 输出完成后重新读取并核对结构及移除范围；任何不确定结果都不能返回可下载的“成功”副本。

复用底层 PDF 对象、字体和写出工具，但不直接把当前含未知内容的 DrawingBatch 当成已清理源。首批不以整页截图绕过内容安全问题。脱敏只针对选择范围，不表示自动查找其他页中的相同信息；预览应提示需由用户选择的其他出现。

## 第 6 批：输出与 PDF 转 Office

### 图片、文本与打印

PNG/JPEG 输出复用核心页面图元和共用 Canvas，支持当前页、页范围及全部页。逐页完成绘制与编码后释放资源；多文件交付沿既有页面图片输出方式，总输出字节和数量继续受限。页面绘制不完整时不能静默生成完整性成功结果。

HTML/Markdown 从核心文字和结构提取生成，支持有把握的段落、列表、表格、图片和链接。HTML 转义文本并按既有策略处理链接，结果不包含可执行脚本或自动外链请求。无法恢复的结构给出页级说明，不宣称版式完全保真。浏览器打印继续使用当前 PDF 原格式输出及既有打印生命周期。

### 提取与目标重建

转换使用已提交源，不读取屏幕像素。PDF 核心补充有界的页面提取：文字/字形 cluster、字体样式、基线/quad、图片、简单线框及页框。语义和绘制完整性继续分别返回；带坐标的少量记录供三种转换共用，不建立跨格式万能文档模型。

`pdf-convert` 在 MoonBit 中按方向完成顺序恢复、相邻文字合并和确定的表格识别，再调用目标核心的 `Session::create`、内容构建和保存。复用原生模型及事务校验；批量构建时在目标格式内部补必要入口，避免每个字形调用一次公开编辑并重新布局。关闭临时会话和资源不影响当前 PDF。

| 方向 | P13 最低可编辑结果 | 不确定情况 |
| --- | --- | --- |
| PDF → DOCX | 常见横排单栏文字的段落/样式、明确分页、普通图片和有明确线框/单元格边界的表格 | 多栏、阅读顺序或复杂浮动不能可靠恢复时返回对应页告警；复杂恢复归 P14 |
| PDF → XLSX | 有明确行列的表格变为单元格，保留文本/数值及基础格式；多个区域按确定顺序分表 | 不把任意散落文字猜成表格；没有可识别表格时明确失败。默认保留含前导零或类型不明的文本，不推断公式 |
| PDF → PPTX | 每页生成一张幻灯片；文字为可编辑文本框，图片为图片，支持的简单图形为原生形状 | PDF 混合页尺寸按目标统一尺寸等比放置并给出说明；复杂图形不冒充可编辑对象 |

三种方向都返回目标字节、源页映射及具体损失说明。结果至少区分成功、带损失完成和失败；整体默认不接受静默丢页。出现无法转换的页面或对象时，先给出可理解的原因，只有明确选择接受损失后才交付相应结果。

扫描页识别为需要 OCR，不把整页图片或空白单元格计为可编辑转换完成。未知 Unicode 不凭视觉猜字；源字体替代及文本顺序变化必须报告。PDF 不包含原始公式、Word 样式或母版关系，转换不能宣称恢复这些源结构。

目标格式预算、PDF 读取预算和总输出限制共同生效。图片解码复用现有平台适配；分析、分组、目标对象和写回留在 Wasm。转换失败不改原 PDF，也不返回半份 Office 文件。

## 资源与阶段边界

保留[现有 PDF 预算](references/formats.md#pdf-输入与文档操作)。新增多页视图、缩略图、跨文件候选和转换同时检查对象数量、解码字节及输出总量，不能为每页重置累计预算。实现时在所属接口记录实际默认值；不预先承诺吞吐、帧率或完整堆峰值。

Web 合并同一帧的指针移动和视口变化，输入优先，按需绘制。核心负责命中、坐标、字体、结构分析和资源失效。Renderer 继续只消费通用图元及覆盖层；不加入分页、PDF 操作符、表单值或转换算法。

同步 Wasm 调用仍不可抢占。搜索、缩略图、逐页输出和转换在可用的页/批次边界检查取消；单次核心工作由预算限制。关闭/替换释放临时资源，旧回复不能覆盖新文档。实际卡死、无法输入或资源失控阻塞功能时当批修复；常规兼容矩阵、缓存专项和性能基准归 P14。

本阶段不引入 PDF.js/PDFium 常驻第二套模型、Worker 池、插件总线、新绘图后端或独立前端转换框架。只有当前依赖缺口确实阻断已列核心功能时，才补底层能力并记录归属和许可。更多字体/色彩/编码、加密阅读和复杂结构归 P14；不借此延后本阶段承诺的普通文字、图片和表单操作。

## 足够检查与完成条件

扩展现有私有 `cases/p7-p8-pdf.json` 及相应格式用例，按功能选择检查；详细输入和证据归[测试说明](references/testing.md)。下面是各批必须证明的结果，不要求每项再创建一套测试或跑全量矩阵。

| 操作链 | 必要证据 |
| --- | --- |
| 新建/阅读 | 新建保存重开；连续/双页、缩略图、搜索与跨页复制不改修订/活动草稿；视图释放后旧资源不能命中；键盘可操作 |
| 页面与文件 | 含共享资源、旋转/裁剪及受支持链接/字段的输入；插入/替换/拆合后引用正确，撤销和失败原子，输出可独立读取 |
| 文字/图片 | 修改后保存重开；文字内容与像素对应，其他共享出现不变；缺字、保护目标和旧修订明确失败；组合输入及草稿取消保持源 |
| 批注/表单 | 每个新增原生类型的必要结构/外观检查；至少一条多 widget、真实导出值和回复关联操作链；保存、历史及删除不留悬空引用 |
| 脱敏 | 正向文字和图片输出；共享资源/字段等危险输入拒绝；独立解析解码流、文本、图片及非视觉载荷后不能恢复已选数据；输出失败不影响源 |
| 转换/输出 | 三方向各有可编辑文本/表格/对象的输入；目标 SDK 再编辑、保存重开并核对原生 XML；扫描/不确定结构有明确结果；图片/打印沿现有路径检查 |

PDF 结构沿用 qpdf，文字/像素沿用 Poppler 等现有独立工具；优先采用固定 ONLYOFFICE 输入与行为，已有 LibreOffice 基线保留真实来源。脱敏不能只查截图或对原始压缩字节搜索敏感词。转换不能只检查扩展名和 ZIP 可打开。

公共字体、图元或 writer 被修改时，增加直接受影响的 Office 输出回归。复用已通过且路径未改变的证据，不为面板文案、样式或机械改名新增快照。只验收 Chrome/Chromium 和现有输入法；不安排其他浏览器、Windows/Word、VoiceOver 或整套性能验收。

六批声明的操作均具备核心/API/UI、保存或输出、明确保护和上述足够证据后，P13 才可完成。实施时把实际 API 与边界写入格式合同；完成后精简本文并移到 `implemented/`，同步索引、路线图和 G3。不能把局部 PASS 写成任意 PDF 兼容。
