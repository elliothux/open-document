# P10 DOCX 核心功能

状态：`planned`，第 1、2、3、4、6 批实施中。依赖已完成的 [P9 Web SDK 与默认 UI](implemented/p9-web-sdk-ui.md)，属于功能优先级 P0。已接通空白创建和另存；其余创作能力仍按下面的范围实施。阶段顺序归[路线图](references/roadmap.md)，当前 API 与限制归[格式合同](references/formats.md)，功能依据归 [G3](g3-genoffice-sdk-gap.md#文档docx)。

当前进度：ZIP/OPC 已支持显式创建，以及一次保存中的新增、替换和删除。DOCX 已接通空白创建、首次保存与另存。字体、字号、字间距、颜色、粗斜体、单下划线、删除线、高亮和上下标，以及段落左右/居中/两端对齐、缩进、段前后距、行距、段前分页已有核心/API/UI、混合查询、清除直接属性与历史。装饰不拆开塑形，上下标参与字号、基线与选区计算；预览与 PDF 使用相同绘制结果。软换行与 Tab 已接入逻辑位置、格式、删除、历史和保存；Tab 支持文档默认间隔和左/右/居中/小数点自定义位置，包含属性继承、显式清除与历史；文档默认间隔也可修改或恢复，表格原生 Tab 移动到相邻单元格，参数面板保持焦点切换。折叠处的格式随实际输入一起提交，取消组合保留输入格式。字面查找、大小写/全词选项、结果定位、单项和全部替换已接通同一队列，旧结果拒绝且不停止编辑。格式复制已通过核心属性片段接通 API/UI，两类格式合为一次历史；混合属性不覆盖目标。竖线与五类引导线也已接通相同格式事务、核心绘制与 PDF；引导线不进入逻辑文字。RTL 段落方向、制表原点、缩进、对齐与竖线已接入核心、API、UI、历史和输出。主题颜色已接通文字、样式继承与列表标记，支持映射和明暗变换、首次主题部件创建、默认面板与精确历史。标题/正文的 Latin、EA、CS 六个主题字体槽已接通批量修改、空槽回退、四字体槽解析、默认面板和精确历史。缺字体预检覆盖正文、表格及所有已存页眉页脚变体，受保护槽保留源并单独禁用。其他内置样式重置规则及后续批次仍未完成，不标记第 1 批或整个 P10 完成。实际签名与边界归[格式合同](references/formats.md#p10-当前格式编辑)。

标题导航与正文逻辑文字统计已接通核心、API 和默认面板。标题采用继承及直接大纲级别，新建文件提供九级标题样式；点击标题可跨页定位并继续原生输入。段末原生 Enter 使用有效后续样式，新建标题恢复正文；中间拆段及粘贴保持原样式，选区删除与换段/样式切换合为一次历史。正文和表格单元格按同一逻辑文字计数，受保护或排除的区域给出原因；统计不包含自动编号及页眉页脚。查询不改源、选择或历史，旧修订和其他文档的导航结果被拒绝。核心、Chromium、安装包与严格宿主编译已检查；其他导航/校对功能仍待实现。定义与边界归[标题导航与正文统计](references/formats.md#标题导航与正文统计)。

水平标尺已接通核心、Wasm/Worker、宿主和默认 UI。首行、悬挂、起始/末尾缩进、制表位及单节左右页边距共用现有事务；鼠标松开只提交一项历史，Escape 取消只清除导线。原点来自焦点行的实际正文、单元格或分栏位置，RTL、缩放及水平滚动沿同一坐标。制表位移动保留引导线和继承清除，键盘可移动/删除并跟随排序后的项。精确历史、保存重开与 PDF 共用既有路径。当前范围与限制归[水平标尺](references/formats.md#水平标尺)。

现有段落与字符样式目录、应用、清除、修改，以及基于现有样式新建和删除自定义样式，已接通核心、API 和默认 UI。它们支持继承、混合查询、撤销和保存重开。应用段落样式时清除段落直接属性；字符样式保留文字直接字符格式。折叠处的字符样式随后续输入提交历史。新建文档提供 Emphasis、Strong、Hyperlink 和 FollowedHyperlink 字符样式。缺少样式部件的导入文件也能创建首个样式，部件、关系与内容类型合为一次历史。样式管理使用正文与其他 Word XML 的同一历史，保留直接覆盖和未改源内容；删除会同步映射样式引用。默认 UI 当前提供名称、基础样式及全部已支持的字符/段落属性修改，以及从所选样式派生或无基础创建、显式选择同类型替代样式后删除。无基础样式的自定义样式也可删除；没有替代项时保持禁用。属性修改区分保持、设置与恢复继承，确认后合为一项历史。默认段落/字符样式及 Normal、DefaultParagraphFont、Strong、Emphasis、Heading1–Heading9，以及 NoSpacing、Quote、Caption、QuoteChar、SubtleEmphasis、IntenseEmphasis、IntenseQuoteChar、Hyperlink、FollowedHyperlink、Title、Subtitle、TitleChar 和 SubtitleChar 已支持显式格式重置，保留身份、名称与正文直接覆盖。链接自定义样式可删除，对端保留并解除链接。共享样式修改先校验继承编号，失败保留原包。其他内置样式重置规则仍待实现。

已接入已有列表的编号读取和标记排版：七类常用格式、九级计数、样式继承、父级重启与起始覆盖，正文和表格按源顺序计算。标记与正文位置分离，预览、PDF 和页面文字使用相同结果。列表创建、应用、移除、级别调整与重启已接通核心/API/UI、单项历史及保存重开。非空 Enter 延续列表，空项 Enter 退出或降级，段首 Backspace 按级别降级或退出。选区删除和空项 Enter 合为一次历史，粘贴换行保持结构输入。列表 Tab 已接入首项定义缩进、后续项与选择的层级调整、混合段落缩进，以及字面 Tab 与表格导航分流；编号级别覆盖、重启和命名空间一起保存。自定义级别的格式、模板、起点、父级重启、对齐、后缀、缩进和标记字符属性也已接通 API/UI、单项历史及保存重开，正文源内容不变。具体边界归[格式合同](references/formats.md#列表读取与标记排版)。

## 3. 第一批的实现设计

### 3.1 新建与多部件事务

先为核心 ZIP/OPC 补两项实际能力：从显式部件集合创建包；在源包中原子新增、替换和删除部件。复用现有路径、XML、解压与输出预算。检查同名冲突、内容类型、关系目标、外链标记和签名限制，保留未改部件的源内容。现有替换保存直接改用扩展后的单一路径，不保留旧实现分支。

DOCX 创建入口生成最小合法包：根关系、主文档、所需样式/设置、内容类型及一个空段落。编号、图片、页眉页脚等部件按实际操作创建。模板由 MoonBit 的格式代码生成，不在 React 中拼 OOXML，也不维护一份只能打开的 base64 空文件。

当前编辑历史已记录正文、样式及其他 Word 部件中样式引用的源片段，并支持首次样式所需的 XML 新增、关系和内容类型，合并校验候选并原子回放。继续扩展一次文档操作涉及的部件变化：已有部件删除、其他对象的关系/内容类型、二进制资源、前后选择及新节点身份。候选全部校验成功后，提交一次 revision 和一项历史。失败保留已提交文档与历史；撤销同时恢复关系、资源和节点身份。

原始包与已提交部件用于保真；类型化样式、段落和对象视图由它们派生。不能另建可独立编辑的 TS 文档树。历史继续有界；新增二进制资源计入资源和历史持有预算，复用不可变字节，不能以只计句柄隐藏内存。仅删除本次操作创建且已确认没有引用的资源；不扫描删除未知部件。

这是 [P11](p11-xlsx-core.md) 和 [P12](p12-pptx-core.md) 复用的包写入能力。它不包含三格式共用的文档事务、位置模型或历史管理器。

### 3.2 格式、范围与输入

延续 UTF-16 offset、字素边界和稳定节点身份。当前位置只有正文段落上下文；进入页眉、脚注等功能时，位置增加所属部件/内容区域。文字范围、表格矩形和对象选择使用可区分的类型，跨内容区域的非法范围明确拒绝。

字符格式操作在核心拆分边界 run，保留范围外属性和未知内容。实现字体、字号、粗斜体、下划线/删除线、文字色/高亮、上下标与清除直接格式。查询区分一致值、混合值和不适用，不能用第一个字符的值代表整个选区。设置、清除和不修改某项属性也必须可区分。

折叠选区改变后续输入属性，不插入空文字伪造文档变化；开始实际输入时与文字一并提交。段落操作明确覆盖被选中的段落，支持对齐、缩进、段前后距、行距、制表位与分页约束。样式修改保持直接格式与继承的区别，检查继承循环；删除被引用样式时显式指定替代样式。

列表使用 numbering 部件的抽象定义、实例、级别和重启规则。编号文字由核心计算与排版，不能把“1.”写进正文来模拟。普通输入、回车、退格与列表降级按 ONLYOFFICE 的对应规则接入现有输入事务。

软换行与段落分隔使用不同的内容节点；Tab 根据正文/表格/输入面板上下文处理。IME 延续已有候选机制，格式菜单不能在组合期间改变其目标。格式刷使用核心返回的属性片段，不复制页面几何。

查找读取逻辑文字，返回绑定 revision 的范围。单次替换与全部替换复用范围事务；全部替换先确定不重叠目标，再一次提交，避免 offset 漂移和部分替换。初期支持字面文本、大小写和全词选项，不前置通用正则执行器。

### 3.3 SDK 与 P9 接入

以下是拟定入口，实施时同步修改桥、Wasm 类型、client、Web 编辑宿主及调用方；不预先发布未实现的空方法。

| 入口 | 最小合同 |
| --- | --- |
| `FoundationSession/Client.createDocx(budget)` | 创建空白会话并返回与打开一致的查询结果；默认页面参数由核心确定 |
| `queryFormatting(revision, selection)` | 返回字符/段落/样式/列表的有效值、混合状态和本操作的限制原因 |
| `setCharacterFormat` / `setParagraphFormat` | 显式 revision、选择和类型明确的属性修改；返回已提交状态 |
| `applyStyle` / 样式和列表操作 | 用稳定身份定位，校验引用与保护；不接受任意 XML 字符串作为编辑协议 |
| `find` / `replaceMatches` | 有界匹配结果、revision 与替换文本；过期结果拒绝 |

Web 编辑宿主在现有队列中补对应方法，默认 UI 使用同一方法。选择属性放入格式状态；全量样式/批注等列表按面板需要查询，React render 不发核心请求。颜色、字体等控件按用户确认提交；拖动预览若确有需求，使用核心候选并在结束时产生一项历史。

P9 的 `mountEditor` 扩展文件输入为“已有 `{ name, bytes }`”或“空白 `{ name, blank: true }`”，以类型联合排除同时传入。实例新增 `create({ name })`，复用 `open` 的草稿/修改确认和独立候选替换。DOCX、XLSX、PPTX 已接通该入口，分别归 P10/P11/P12；PDF 留到 P13。不为未知格式生成占位文件。

新建文件即使尚无编辑，也需要首次保存。P9 当前按 revision 与保存基线判断修改；这里补“尚未持久化的新文档”状态，保存回调成功才清除，下载仍不代表持久化。放弃关闭和晚到保存回执沿 P9 规则处理。

另存使用用户指定的新名称与现有输出/保存回调，存储目标由宿主确定；失败保留原名称和修改状态。故障恢复继续提供已提交状态的保存/恢复副本下载，未提交候选按现有恢复规则处理，不把失败的半成品当成恢复文件。

## 4. 后续批次的关键设计

### 页面、内容区域与表格

节拥有页面参数、栏、页码和页眉页脚引用。核心按内容顺序解析节边界，布局先确定页/栏可用区域，再排段落和表格。页眉页脚的首次/奇偶页及“链接到前一节”属于文档语义；修改共享部件与断开继承是两种明确操作。命中结果带内容区域身份，不能把页眉坐标映射到正文。

表格以逻辑网格计算合并区域和单元格跨度。插入/删除、合并/拆分先计算最终结构与内容去向，再修改 XML；合并涉及多格内容时保留其段落顺序。边框冲突、自动宽度、单元格边距和垂直对齐由核心求值。跨页布局提供重复表头与可拆行的延续状态，行不能无界重试分页。复杂嵌套和浮动表格另入 P14，普通长表不能因此仅支持一页。

### 图片、浮动对象与富文本片段

已有正文行内图片的尺寸、四边裁剪与重置已接通核心、同步 Wasm、Worker、宿主和默认图片面板。源图片、关系、替代文字及其他 XML 保留；命令使用列表的 revision，保持原文字选择，并独立于原生输入进入精确历史。核心保留图片框和源裁剪，Canvas/PDF 使用同一裁剪结果；保存重开后仍可继续修改。核心与 Chromium 已检查源、保护、资源、历史、原生输入及真实裁剪像素。图片删除已接通同一 API 和面板，保留共享资源，并支持删除后文字输入及精确混合历史。图片替换也已接通，保持原框和裁剪，独立创建资源并纳入同一历史。正文行内 PNG/JPEG 图片新增已接通，支持当前文字范围替换、空段和单个普通单元格，资源与源 XML 共用一项历史。插入后显示图片属性，光标落在图片之后。受支持图片段落已接通原生输入、组合、格式、查找替换、拆段合段及按范围/退格删除图片，并保留精确混合历史。已有图片点击选择、准确选区、面板自动定位及原生删除/替换，保留缩放、扩选与精确历史；四角等比例拖动缩放和方向键缩放已接通，使用核心候选预览、取消及单项历史，保留裁剪和资源；更多浮动对象仍待实现；当前签名和上限归[行内图片尺寸与裁剪](references/formats.md#行内图片尺寸与裁剪)。

正文图片的行内/前置/后置切换、两轴参考系与偏移/对齐及层次顺序已接通核心、Wasm/Worker 和默认面板。图片保留逻辑位置，浮动框不增加行宽与行高；纸张/源页边距/当前栏/段落定位、图层、命中和完整选区使用同一 Canvas/PDF 几何。精确历史、源/资源保留、重开输入及输出已检查。上下型环绕与四边文字间距也已接通同一核心、API 和面板，正文/表格避让、整页图片与文字续页、缓存、保留段落/孤行、布局失败原子性及 Canvas/PDF 已检查。方形环绕也已接通四种侧向，两侧文字共用行、基线、光标与选区；段落/表格同页、RTL、编号、缓存、原生源和保存重开已做定向检查。正文浮动图片已接通选中后的拖动与方向键移动，复用候选、取消和最终坐标的单项历史；SDK 已接通显式目标位置的跨段重锚，保留原运行格式、身份、资源及精确混合历史；跨页迁移、保存重开与 Canvas/PDF 已检查。指针拖动已接通跨段/跨页重锚及边缘滚动/翻页，候选选区随新锚点展示，取消恢复原选择；更多浮动对象继续实施；参数与保护归[图片定位](references/formats.md#图片定位)。

剪贴板片段由核心输出逻辑结构、格式和资源引用。内部粘贴重映射节点、关系和样式身份；跨文档资源随片段有界携带。HTML/Markdown 在导入边界转换为同一片段，再进入核心事务。HTML 只接受声明的元素/属性，移除脚本与事件属性，不发起外链资源请求；保留格式/匹配目标格式/纯文本是明确选项。不能把浏览器 DOM 变成排版权威。

### 图表、数学与输出

图表保存图表部件、系列/轴/样式、嵌入工作簿及关系，系列缓存与数据保持一致。P10 只要求所建图表使用的矩形数据读写；在 XLSX 所属模块补这项内部能力，由 P11 扩展为工作簿编辑，不等待 P11 全部功能，也不在 DOCX 中实现第二个电子表格引擎。

数学结构读取/写回 OMML，核心根据字体度量排上下标、分数、根式与矩阵，输出已有路径/字形。LaTeX 是输入表示，不是无界宏语言；不支持的语法拒绝而非降成不可再编辑的图片。图表/数学只在第二处实际复用时提取共用布局代码。

PDF 继续使用核心布局；图片输出由平台对相同绘制结果编码，分别声明平台依赖。HTML/Markdown 从核心逻辑内容导出，明确表格、浮动、字段等降级，不静默丢弃。打印消费已生成页面/PDF；浏览器负责打印对话框，不负责重新分页。输出只读，不清除原格式未保存状态。Web 当前页 PNG 已接通宿主 API 和默认菜单，可配合页导航逐页输出；复用核心 R0、输入屏障和 Canvas 编码，保留源、选择、历史及修改状态，并检查布局诊断、像素/字节预算和失败恢复。全页 PNG 集合、总字节预算、自动逐页命名和默认逐页保存/下载也已接通；部分宿主保存失败保留已完成进度与原文档，重试使用当前修订。合同归[DOCX 页面 PNG](references/formats.md#docx-页面-png)。

正文 HTML/Markdown 导出已接通核心、同步/Worker API、宿主输出屏障和默认文件菜单。文字、标题、链接/书签、表格合并及内嵌 PNG/JPEG 已检查，保留原生源、精确历史和未保存状态；HTML 保留可用外观，Markdown 用内嵌 HTML 表达复杂内容。列表已有原生嵌套、续号、重启和空项，Markdown 普通列表使用原生语法，复杂格式与 RTL 使用结构化 HTML。特殊标签沿核心保留字面外观和实际数值；页眉页脚、审阅身份、字段和未知结构明确拒绝。字体及页面几何的降级和预算归[HTML 与 Markdown 合同](references/formats.md#docx-html-与-markdown)，更广区域、导入和打印 UI 继续实施。

## 5. 布局更新与薄 Renderer

每种命令报告实际影响的内容区域、段落/对象或资源。沿现有段落缓存、稳定点分页和 R0 更新：改字符重排相关段落，改节参数重排相关节，改共享样式按引用确定受影响范围。依赖无法安全收敛时，在既有预算内完整重排；不以不完整的失效信息换取速度。

Renderer 继续消费位置已确定的图元、资源和覆盖层。新增表格、图表、数学和浮动语义放在核心；Web 仅做视口、事件合并、资源准备与像素绘制。按功能消除实际卡死和不可交互，缓存平台、基准矩阵与专项性能门槛留到 P14。
