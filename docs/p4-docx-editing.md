# P4 DOCX 编辑与保真保存

状态：`planned`。2026-10-11 细化。本文定义待实现行为与验收条件，不表示编辑 API、fixture 或验证环境已经就绪。当前能力仍以[格式合同](references/formats.md)为准。

## 1. 用户结果与范围

开发者可以在 Web 应用内嵌入一个有限但真实可用的 DOCX 编辑器：打开文档，点击定位，选择和输入文字，拆分或合并段落，撤销/重做，保存 DOCX，并从当前排版导出 PDF。程序化 API 和浏览器交互修改同一份 MoonBit 文档状态。

首个可用切片必须完成「真实 DOCX → 点击光标 → 输入/删除 → 撤销/重做 → 保存 → 独立重开」。不能只提供命令 API、输入框或静态预览就宣告 P4 完成。

| 范围 | P4 承诺 | 不在本阶段内 |
| --- | --- | --- |
| 输入文件 | 延续 P2 的有界 ZIP/XML/OPC 与 Transitional DOCX；逐操作判断可编辑范围 | Strict、加密、宏执行、旧 DOC、签名安全改写 |
| 正文编辑 | 普通段落中的文本；跨受支持 run 的范围替换；相邻正文段落拆分/合并；保留已有格式 | 新增格式工具栏、编号编辑、修订/批注编辑、域更新、复杂内容控件 |
| 表格与图片 | 在 P3 受支持表格的单个单元格内编辑普通文本；已有内联图片和非目标结构保持 | 跨单元格删除、表格结构编辑、图片插入/删除/拖拽、浮动对象编辑 |
| 浏览器输入 | 光标/选区、键盘与指针、中文 IME、纯文本复制/剪切/粘贴、基本无障碍交互 | 富 HTML/RTF/图片粘贴、移动端编辑、完整 Word UI、协作 |
| 输出 | 保存、重新打开、重复往返；使用同一布局的预览和 PDF | PDF 输入编辑、PDF/A/UA 认证、任意格式互转 |

当前布局不支持的内容不会因为能保留 XML 就变得可编辑。编辑器应展示诊断并限制操作；不能在不可见的修订、域、书签或未知结构上执行有损范围替换。对未知标记的处理见第 3 节。

## 3. 实现合同

### 3.1 文档状态与源内容保留

`formats/docx` 的 Session 拥有唯一可编辑状态：受支持的段落/run 内容及其原始 XML、未知片段和 OPC 关系。查询、Flow、Layout 和宿主文本窗口均是派生结果。结构写回能力放在 `core/xml`，DOCX 的段落/样式规则留在 `formats/docx`；不创建跨 XLSX/PPTX 的万能编辑树。

从现有源片段表示演进：稳定节点身份不使用会随重新解析变化的数组下标；修改只替换相关内容，未动节点继续引用原材料。具体容器随 P4.1 探针确定，不预选 rope、piece table 或整文档快照历史。旧 replacements 路径在新命令落地后接入同一权威状态，不能长期维护两套编辑引擎。

保真规则：

- 未改 OPC part 的解压字节与原输入相同；修改 part 的非目标元素、属性、关系及未知片段保持。XML 编码转换等既有例外沿用 P2，分别核对语义与适用的词法保留，不能笼统要求整个 ZIP hash 不变。
- 编辑开始前识别可安全改动的范围。普通文本旁的未知属性可保留；包含未知内联节点、域、修订、书签/批注边界或内容控件时，先保护受影响段落/结构范围，拒绝会跨越或改变其语义的操作。无法确定边界时扩大只读范围并给出位置与原因，不静默删除，也不把整个文件所有无关正文一律禁用。
- 已有内联图片是受保护对象；光标可以位于其前后，但 P4 不删除、移动或把它变为字符。跨图片、跨表格边界和跨单元格的修改整体拒绝，不执行前半段。
- 已改 part 必须通过预算、XML 与关系校验后提交。保留源片段不能成为逃过关系/命名空间检查的理由。

### 3.2 位置、选区与命中

位置使用会话内稳定结构 ID、段落局部 UTF-16 offset 和必要的前/后 affinity；偏移对应逻辑内容，不是 XML 序列化字节。段落分隔和内联对象有明确的逻辑位置规则，不混入 `w:t` 字符计数。选区保留 anchor/focus，不能只存排序后的起止点。

命令在核心中验证位置、revision 和可编辑范围。外部旧位置不自动猜测；陈旧 revision 或已删除 ID 明确失败。核心拥有的当前选区通过事务映射更新；撤销/重做恢复内容和选区，但 revision 继续单调增加，不能让旧请求重新有效。

用户导航和删除以扩展字素簇为边界；不得拆开 surrogate、组合字符或 ZWJ 序列。glyph cluster 不等于字素簇，不能直接作为所有编辑边界。P4.1 需验证 MoonBit 字素分段实现及固定 Unicode 版本；若现有依赖不足，先完成标准向量探针，不转交 TS 的另一套分段规则。字体无法显示的输入仍须明确诊断，不借机承诺彩色 emoji 渲染。

`layout` 根据真实 shaping/BiDi 与源映射返回光标和选区几何，覆盖连字内部的合法位置、双向交界 affinity、软换行两侧、空段落与段落末尾。核心决定视觉左右和上下导航、Home/End 及跨行目标；宿主仅把 CSS 像素按缩放/DPR 转成页面 point，再绘制结果。禁止 DOM 测量或等分字符宽度重建排版；缺少连字 caret 数据时须在探针中明确几何策略并以独立参考验收。

命中请求绑定 layout ID、页面和坐标。过期布局、非法页面和非有限坐标失败；不能在旧画面上套用新文档位置。点击行内空白取合法最近边界，点击受保护对象返回不可编辑结果，而不是落到任意文字。

### 3.3 命令、事务与历史

首批命令语义为范围替换、前/后删除、拆段、合段、撤销和重做；本文不冻结具体 TS 方法名。段内输入、粘贴和选区删除复用范围替换，不维护键盘专属文档修改代码。

- 每次命令先构建和校验候选变化，成功才一次提交内容、选区、历史与失效范围。失败不改变这些状态；无变化命令不增加 revision、不清空 redo。
- 成功内容修改、撤销、重做均增加 revision；仅移动选区不增加文档 revision。结果包含新 revision、选区、可撤销状态、受影响范围及诊断，不返回整份可编辑树。
- 插入继承位置的有效字符格式；run 边界用明确的 affinity 决定继承侧。范围替换保留范围外文本和格式，新增文字采用范围起点的插入格式。
- Enter 拆段保留字符格式，继承当前受支持段落属性；一次性段前分页留在原段，不复制到新段。合段保留前段段落属性、两侧存活 run 的字符格式。涉及编号、节边界或未解释属性时拒绝结构变更，不猜 Word 行为。
- 历史保存有界的局部前后内容与位置变化，不为每个字符复制整个 ZIP/布局。原子粘贴、拆/合段各一项，IME 一次提交一项；连续普通输入按核心认可的显式输入组归并，换位置、换命令、粘贴和组合输入均结束旧组。
- 同时限制历史条目、保留字节和单次命令输入；P4.1 用实测确定并固定默认值及 N−1/N/N+1 测试。超大单命令拒绝；容量不足时可淘汰最旧完整历史项，返回新的可撤销边界，不隐藏丢弃。新编辑清空 redo，保存不清空历史。

### 3.4 输入、异步与保存

浏览器的输入元素仅承载平台需要的短期文本窗口和 composition，不作为文档模型或最终排版。选区语义与组合输入的暂存变化属于核心；TS 转发事件、维护传输顺序、定位候选窗和恢复焦点。

一条会话仍按顺序处理命令。宿主需要有界队列应对快速输入，而不是把当前「Await the previous operation」直接暴露为丢字；待发的是输入意图，不是第二份可编辑状态。发送时使用已确认 revision；程序化并发修改导致冲突时明确终止相关输入组并重新取得状态，不盲目重放。仅未发出的同一 composition 暂态更新可合并；已提交输入、剪贴板和撤销不能丢弃。队列耗尽时停止接收新编辑并明确提示，不能默默丢字。

composition 更新产生暂态预览，不进入已提交历史；提交一次落盘语义变化，取消还原初始内容与选区。组合期间保存、导出、撤销或外部编辑返回明确 busy 结果，宿主提示先完成/取消输入；失焦依实际 composition 事件处理，不猜测提交。必须覆盖中止、空提交、重复终止事件和销毁，不仅是正常输入。

普通保存在此前已接收的编辑之后作为顺序屏障执行，绑定确切 revision，后续输入不改变该输出。宿主文件写入/下载不由核心保证；取消下载不能倒退文档，失败保留可再次保存的会话。保存的 revision 与当前 revision 分开呈现。PDF 绑定当前已完成的 layout ID；重排未完成或画面过期时不能下载一个不同版本的 PDF。

只接收纯文本粘贴：换行规范化为逻辑段落分隔，tab 使用明确受支持的表示；若 tab 编辑/布局未就绪则拒绝含 tab 的粘贴并诊断，不能替换为空格。HTML/RTF 不导入、不执行，外部资源不自动获取。剪切先确认剪贴板写入，再按原 revision 删除；写入失败或期间文档变化不删除内容。

销毁时拒绝所有等待请求、终止 Worker、清除暂态和监听器、释放位图与 Canvas 资源，保留宿主其他 DOM。同步 Wasm 仍不能抢占；硬超时终止会话且明确未保存内容可能丢失，不宣称自动恢复或后台持久化。

### 3.5 排版失效与性能路径

P4.1 允许正确的整篇重排以建立基线；从第一版就返回真实受影响内容范围。P4.4 复用未变段落的塑形结果，从最早受影响页开始重新分页，直到页面边界及后续布局状态稳定。前文增字可能改变后面所有页，不能承诺只重排一页。

核心布局、Canvas 和 PDF 使用同一 revision/资源/profile。只移动光标不重新解析 DOCX、塑形整篇或序列化 ZIP。字体/profile/图片变化按真实依赖失效；缓存是派生值，关闭会话后释放。长无空格段落的优化必须保留整段 BiDi、上下文塑形与原先几何断言，不以逐字符 advance 替代。

| F6 规模与真实反例 | F1 真实文件；独立生成固定规模的多段/多页文档、1K/2K/4K UTF-16 长无空格段；真实产品缺陷原件与缩小反例 | 长段风险已知；编辑 workload、校准和缺陷选择待完成。超出当前预算单列拒绝，不抬高预算获得通过 | 每轮编辑后独立文本/结构正确性；分页/像素参考；性能原始样本和资源趋势；固定测试的真实产品修复比较 |

F1、F4 优先从 [LibreOffice OOXML 回归](https://github.com/LibreOffice/core/tree/1746b16a564f59fcaf8c5670bb292748408da54e/sw/qa/extras/ooxmlexport)和 [Writer 交互回归](https://github.com/LibreOffice/core/tree/1746b16a564f59fcaf8c5670bb292748408da54e/sw/qa/extras/uiwriter)挑选「原文件 + bug + 断言」。筛选完成后，精确文件和操作登记到私有清单；来源目录链接不等于 fixture 已准备完成。没有授权的业务文件不引入，也不把上游文件称作本项目客户文档。

## 6. 兼容性 profile 与独立判定

| Profile | 用途与门槛 | 未满足时 |
| --- | --- | --- |
| Node library + Chromium Worker | 使用同次 release Wasm 和实际包；Node 固定现有版本，Chromium 固定 Playwright 版本及实际 build。共享操作检查文本/错误/历史/保存；UI 另验真实事件 | 对应子阶段不能通过；Node 成功不能代替 browser |
| 固定 LibreOffice | 复用 P3 的 25.8.2.2、授权 Noto 字体及 profile；校准后新增编辑输出的重开、文本/属性、页数/几何与 PDF | 缺 oracle 为未确定；不得借用未编辑文件的旧 PDF |
| Microsoft Word | P4 目标为 Windows 11 上 Microsoft 365 Word 桌面版的明确 build；这是待落实的验证目标，不是已有环境。P4.1 登记取得方式和负责人，P4.4 前固定 build、OS、字体、兼容模式及审核步骤 | 当前未验证。缺少授权环境时，P4.4 的微软兼容验收保持未完成；若需调整目标平台，先由维护者决定，不能拿 LibreOffice 结果替代 |
| 实际中文 IME / 无障碍 | 首个输入验收 profile 为开发 macOS + 固定 Chromium + 系统简体拼音，记录 OS/输入源；键盘与屏幕阅读器另记录实际组合和操作证据 | 自动化 composition 用例不能抵扣；其他 OS/IME 未声明支持，不因此声称 Windows 输入通过 |
| Firefox / WebKit | 在现有 G2 试跑上增加 P4 输入与编辑合同，作为显式探索档 | 未通过不扩展浏览器支持范围；Playwright WebKit 不等于 Safari/移动端验收 |

当前仍只承诺 P3 支持的字体、图片和有限布局。Word profile 首先裁定受支持编辑的内容/样式/保留及重开无修复提示，再对声明的视觉样本验证页数、文本位置和图像；不宣称所有 Word 文件逐像素相同。

每份保存案例至少分开记录 no-op、指定编辑、undo/redo 后保存、三轮保存→独立重开→SDK 重开。检查文字与属性、未知内容、关系、非目标 part、参考应用诊断；SDK 自读只证明内部一致性。文本、导出 XML、页面几何、Canvas/PDF 像素和实际交互分别判定。

对于独立参考冲突，先归类为格式规则、指定 Word profile 行为、LibreOffice 差分或项目显式裁剪。保留冲突输入与输出，由维护者裁定合同再修改预期；Agent 不自行选最容易通过的参考。公开上游只能提供行为线索，不能生成本 SDK 独立答案的循环依赖。

## 7. 性能与资源验收

P4.1 先测，P4.4 再依据冻结基线验收；不得直接沿用 P3 的 4.7 秒诊断结果作为交互预算，也不虚构 16 ms 等 SLA。单独计时与端到端计时不混用：

| 指标 | 区间、单位与负载 | 通过条件 |
| --- | --- | --- |
| 首次编辑可用 | 字节已取得至首屏可点击，ms；分列 Wasm/Worker 初始化、解析、布局、呈现；F1/F6 冷/暖运行 | 固定环境校准并冻结预算；缺字体/布局失败不能记为更快 |
| 命令和输入延迟 | library 命令返回 ms；browser 事件至正确 revision 的首帧 ms，含队列/bridge/重排/绘制；段首中尾、跨 run、IME 与粘贴 | 输出正确后才纳入性能比较；记录 median/p95、样本数和离散度，P95 样本不足仅作描述 |
| 命中与局部重排 | 命中 ms、重塑段数、重排页数、传输字节；光标移动、多页开头增删和长段 | 光标移动不触发整文档重建；编辑影响范围与实际分页一致；优化不得改变冻结文字/几何 oracle |
| 历史与长会话 | 历史保留 bytes/条目、队列长度、资源计数；固定操作序列重复若干轮，包含关闭重开 | 达到声明上限后有界淘汰/拒绝；资源计数回落，不能用 GC 尚未回收的 RSS 波动判定必然泄漏 |
| 保存与 PDF | 核心至宿主输出 ms、输出 bytes、同 revision 正确性；多轮编辑和往返 | 不退化到冻结预算之外，错误输出不计成功；保存/输出预算 N−1/N/N+1 明确 |
| 构建与包体 | release 构建时间 ms、Wasm 原始/压缩 bytes、JS bytes、固定字体单列 | 和 P4.1 基线对照，新增依赖成本有解释；不把 fixture/字体混入 SDK 包体 |

校准在固定空闲机器串行执行。复用 G2 当前 5 次预热、20 对 A/A 和 20 对交错 A/B 的方法；输入端到端场景另补实际事件采集，不用 Node 数据顶替。先记录 A/A 噪声和用户操作需求，维护者批准按 workload 的退化预算后固定到私有清单，再验优化版本。高噪声记未确定，不边跑边放宽阈值。

可靠 WasmGC 峰值内存目前不可测，应写 `measured: false`，不填零，也不把线性内存或 Node RSS 当总峰值。P4 的资源门槛先采用可复核的字节预算、历史上限、队列与释放计数；若目标负载出现实际内存问题，先补测量和修复再验收，不将这一限制当作无限内存许可。

## 8. 执行、Agent 反馈与完成条件

复用根 `bun run test` 和 [G2](implemented/g2-test-pipeline.md) 的冻结运行。P4 新增 Moon overlay、library/Worker 共享操作、browser 交互、参考重开与性能用例时，同步更新私有必选集合与包清单；当前没有现成 `test:p4` 命令，若增加选测入口必须标明不能授予完整通过。

实现者负责将 F1–F6 变成固定 case。测试维护者审核输入来源、判定器及新预算；需要人工的 Office/IME 记录由有环境权限的维护者执行，记录操作者、版本、步骤和原始产物，不能由 Agent 推测通过。

沿用现有 `run.json`、`results.jsonl`、`summary.md`、`index.html` 和失败任务。在 P4 失败中补充具体操作序列、选区/affinity、前后 revision、layout ID、IME 事件顺序、expected/actual、part/节点位置、输入输出 hash、原文件、缩小反例、trace/截图及性能样本。人工检查记录要进入验收清单，缺证据不能在自动报告里显示为已通过。

P4.4 至少完成一次真实产品缺陷的改进循环：冻结失败输入和独立预期 → 生成可复现任务 → Agent 修复一般规则 → 原件和最小反例双路径复测 → 相邻回归 → 根完整验收与相关性能比较。允许源码变化，但输入、判定器和预期保持固定；若发现预期本身错误，另走人工审核并保留原失败，不算同一次产品修复成功。不能拿关闭故障注入开关代替。

阶段完成须同时满足：

1. P4.1–P4.4 的产品路径实际可用，核心与宿主职责未偏移；没有另一套 TS 文档模型或 DOM 排版。
2. 本文承诺的每项操作均绑定 fixture、独立预期、surface/profile 与必选 case；正向、负向、边界及 P0–P3 回归实际执行。零执行、skip、缺项、超时、基础设施失败不能通过。
3. 真实文件覆盖读取、编辑、保存、重复往返和非目标内容保真；中文 IME 与 Word 必要证据齐备。缺一项时保留具体子阶段未完成，不把平台缺失写成 accepted limitation。
4. 性能预算已校准、审核、固定；优化前后正确性一致，长会话资源有界。修改 public API 后完成实际 tarball 导入/构建与 Worker 路径验证。
5. 判定器负向探针能抓到错误文本、破坏非目标内容、失效选区/旧布局和遗漏必选用例；保留负向证据后再跑正常完整验收。
6. 更新格式/API/开发合同的实际能力与限制，最后才按文档规范精简归档；本方案不授权提交、推送或发布。

停止扩大实现的条件：无法保留未知内容；必须依靠第二套模型才能输入；真实 IME 丢字/重复提交；新编辑破坏已支持文件；关键 Unicode/字体路径不满足要求；性能仍不适合已冻结负载；需要未授权环境、许可或业务文件。保留证据并解决对应前置条件，不通过减少必选样本、扩大静默降级或转移计算路径取得通过。
